## 1. 개요

**현재 수준**: Java 개발자로서 기본 자료구조/알고리즘 사용 가능. 코딩 인터뷰 체계적 준비 경험 없음.
**학습 목표**: LeetCode Medium 문제를 30~40분 내 풀이 가능. 시간/공간 복잡도를 코드 작성 전에 분석 가능. 시니어 면접에서 "떨어지지 않을 정도" 달성.
**분기 배정**: 전 분기 (1~3분기, 주 3~4회 루틴)
**학습 방식**: 주 3~4회, 40분~1시간. 9개월 내내 꾸준히. Claude에게 문제 풀이 접근법/풀이 리뷰 질문.

### Step 1. 시간/공간 복잡도 분석 — Big-O

| 학습 항목 | 학습 목표 |
|----------|----------|
| Big-O 표기법 | O(1), O(log n), O(n), O(n log n), O(n²), O(2ⁿ) 각각의 의미를 설명 가능. 입력 크기별 어떤 복잡도까지 허용 가능한지(n ≤ 10⁶이면 O(n log n)까지, n ≤ 20이면 O(2ⁿ)도 가능) 판단 가능. |
| 시간 복잡도 분석 | 반복문 중첩 횟수, 재귀 호출 횟수로 시간 복잡도를 계산 가능. 코드를 작성하기 전에 "이 접근법은 O(n²)이니까 n=10⁵에서 TLE가 난다"를 판단 가능. |
| 공간 복잡도 분석 | 추가 배열, 해시맵, 재귀 호출 스택이 차지하는 메모리를 분석 가능. "이 풀이는 O(n) 추가 공간이 필요하다"를 코드 작성 전에 판단 가능. |
| 상수 계수와 실전 | Big-O가 같아도 상수 계수 차이로 실제 성능이 다를 수 있음(예: O(n)이지만 내부 연산이 무거운 경우)을 이해. |

### Step 4. 투 포인터 + 슬라이딩 윈도우

| 학습 항목 | 학습 목표 |
|----------|----------|
| 투 포인터 개념 | 정렬된 배열에서 양쪽 끝에서 좁혀오는 패턴(Two Sum II), 같은 방향으로 이동하는 패턴(Remove Duplicates)을 구분하여 적용 가능. |
| 슬라이딩 윈도우 | 고정 크기 윈도우(Maximum Average Subarray)와 가변 크기 윈도우(Minimum Size Subarray Sum, Longest Substring Without Repeating Characters)를 구분하여 적용 가능. |
| O(n²) → O(n) 최적화 | 브루트포스 O(n²)를 투 포인터/슬라이딩 윈도우로 O(n)으로 줄이는 사고 과정을 설명 가능. |
| 대표 문제 유형 | 3Sum, Container With Most Water, Longest Substring Without Repeating Characters, Minimum Window Substring 유형을 풀 수 있음. |

### Step 5. 스택 + 큐 + 덱

| 학습 항목 | 학습 목표 |
|----------|----------|
| 스택 (LIFO) | 괄호 매칭(Valid Parentheses), 역순 처리, 히스토리(Undo) 패턴에 스택 활용 가능. |
| 단조 스택 (Monotonic Stack) | 다음 큰 원소(Next Greater Element), 히스토그램 최대 넓이(Largest Rectangle in Histogram) 패턴을 이해하고 적용 가능. O(n²) → O(n) 최적화 원리를 설명 가능. |
| 큐 (FIFO) | BFS 탐색, 작업 대기열 패턴에 큐 활용 가능. |
| 덱 (Deque) | 양방향 삽입/삭제. 슬라이딩 윈도우 최대값(Sliding Window Maximum)에 활용 가능. |
| 대표 문제 유형 | Valid Parentheses, Min Stack, Daily Temperatures, Sliding Window Maximum 유형을 풀 수 있음. |

### Step 7. 정렬 알고리즘

| 학습 항목 | 학습 목표 |
|----------|----------|
| 비교 기반 정렬 | Merge Sort(O(n log n), 안정), Quick Sort(평균 O(n log n), 불안정, 최악 O(n²))의 동작 원리를 설명 가능. 각각의 장단점과 선택 기준을 설명 가능. |

| 정렬 활용 패턴 | 정렬 후 투 포인터, 정렬 후 이진 탐색, Merge Intervals 패턴에 정렬을 전처리로 활용 가능. |

### Step 8. 이진 탐색

| 학습 항목 | 학습 목표 |
|----------|----------|
| 기본 이진 탐색 | 정렬된 배열에서 O(log n) 탐색. while (left <= right) 구조와 mid 계산(오버플로 방지: left + (right - left) / 2)을 정확히 구현 가능. |
| 변형 패턴 | Lower Bound(첫 번째 ≥ target), Upper Bound(첫 번째 > target)를 구현 가능. 경계 조건(off-by-one)을 정확히 처리 가능. |
| 답에 대한 이진 탐색 | "최솟값의 최댓값" / "최댓값의 최솟값" 유형에서 답을 이진 탐색하는 패턴(Parametric Search)을 적용 가능. |
| 회전 배열 탐색 | Search in Rotated Sorted Array 유형에서 정렬된 반쪽을 판별하여 탐색 가능. |
| 대표 문제 유형 | Binary Search, Search in Rotated Sorted Array, Find Minimum in Rotated Sorted Array, Koko Eating Bananas 유형을 풀 수 있음. |

### Step 9. 트리 — 이진트리, BST

| 학습 항목 | 학습 목표 |
|----------|----------|
| 트리 순회 | 전위(Preorder), 중위(Inorder), 후위(Postorder), 레벨 순회(BFS)를 재귀/반복으로 구현 가능. 각 순회의 용도를 설명 가능(중위 = BST 정렬 출력). |
| 이진 트리 기본 문제 | 최대 깊이, 좌우 반전, 대칭 판별, 경로 합 패턴을 재귀로 풀 수 있음. |
| BST (이진 탐색 트리) | BST의 성질(왼쪽 < 루트 < 오른쪽)을 활용한 검색/삽입/삭제를 구현 가능. 중위 순회가 정렬 순서인 이유를 설명 가능. |
| BST 활용 | 유효한 BST 판별(Validate BST), k번째 작은 수(Kth Smallest), 최소 공통 조상(LCA) 패턴을 풀 수 있음. |
| 대표 문제 유형 | Maximum Depth, Invert Binary Tree, Validate BST, Lowest Common Ancestor, Binary Tree Level Order Traversal 유형을 풀 수 있음. |

### Step 10. 트리 — 힙, 우선순위 큐

| 학습 항목 | 학습 목표 |
|----------|----------|
| 힙 (Heap) 구조 | 완전 이진 트리 기반, 최소 힙/최대 힙의 성질을 설명 가능. 삽입 O(log n), 삭제(최솟값/최댓값) O(log n), 조회 O(1)을 설명 가능. |
| PriorityQueue | Java PriorityQueue(기본 최소 힙) 사용법, Comparator로 최대 힙 전환, 커스텀 정렬을 적용 가능. |
| Top-K 패턴 | K번째 큰/작은 원소, 빈도 Top-K를 힙으로 O(n log k)에 풀 수 있음. 전체 정렬 O(n log n) 대비 장점을 설명 가능. |
| 두 개의 힙 패턴 | 중간값 구하기(Find Median from Data Stream)에 최대 힙 + 최소 힙을 사용하는 패턴을 적용 가능. |
| 대표 문제 유형 | Kth Largest Element, Top K Frequent Elements, Merge K Sorted Lists, Find Median from Data Stream 유형을 풀 수 있음. |

### Step 11. 그래프 — BFS, DFS

| 학습 항목 | 학습 목표 |
|----------|----------|
| 그래프 표현 | 인접 리스트(Adjacency List)와 인접 행렬(Adjacency Matrix)의 차이와 선택 기준(희소 그래프 → 리스트)을 설명 가능. |
| DFS (깊이 우선 탐색) | 재귀/스택 기반 구현 가능. 연결 요소 개수, 사이클 감지, 위상 정렬에 활용 가능. |
| BFS (너비 우선 탐색) | 큐 기반 구현 가능. 최단 거리(가중치 없는 그래프), 레벨 탐색에 활용 가능. |
| 그리드 탐색 | 2D 배열에서 BFS/DFS로 섬 개수(Number of Islands), 최단 경로 탐색 가능. 방문 배열 사용 이유 설명 가능. |
| 위상 정렬 (Topological Sort) | DAG에서의 순서 결정. 코스 선수과목(Course Schedule) 유형에 적용 가능. Kahn's Algorithm(BFS 기반)과 DFS 기반 방법을 알고 있음. |
| 대표 문제 유형 | Number of Islands, Clone Graph, Course Schedule, Word Ladder 유형을 풀 수 있음. |

### Step 12. 그래프 — 최단 경로

| 학습 항목 | 학습 목표 |
|----------|----------|
| 다익스트라 (Dijkstra) | 가중치가 양수인 그래프에서 단일 출발점 최단 경로. 우선순위 큐 기반 구현 O((V+E) log V)을 구현 가능. 음수 가중치에서 동작 안 하는 이유를 설명 가능. |
| 벨만-포드 (Bellman-Ford) | 음수 가중치 허용. O(VE) 시간. 음수 사이클 감지 가능. 다익스트라와의 선택 기준을 설명 가능. |
| 플로이드-워셜 | 모든 쌍 최단 경로. O(V³). 작은 그래프에서 활용. 존재를 알고 있으면 충분. |
| 대표 문제 유형 | Network Delay Time(다익스트라), Cheapest Flights Within K Stops 유형을 풀 수 있음. |

### Step 13. DP (동적 프로그래밍) — 기초

| 학습 항목 | 학습 목표 |
|----------|----------|
| DP 개념 | 중복 부분 문제(Overlapping Subproblems) + 최적 부분 구조(Optimal Substructure)가 있을 때 적용 가능함을 설명 가능. |
| Top-down vs Bottom-up | 메모이제이션(재귀 + 캐시)과 타뷸레이션(반복문 + 테이블)의 차이를 설명 가능. 각각의 장단점(Top-down: 직관적/스택 오버플로 위험, Bottom-up: 효율적/점화식 필요)을 설명 가능. |
| 점화식 도출 | 문제를 보고 "dp[i]가 무엇을 의미하는가"를 정의하고, 이전 상태와의 관계(점화식)를 도출하는 사고 과정을 설명 가능. |
| 1차원 DP | Climbing Stairs(dp[i] = dp[i-1] + dp[i-2]), House Robber(dp[i] = max(dp[i-1], dp[i-2] + nums[i])) 패턴을 풀 수 있음. |
| 대표 문제 유형 | Climbing Stairs, House Robber, Coin Change, Longest Increasing Subsequence 유형을 풀 수 있음. |

---

### Step 14. DP (동적 프로그래밍) — 중급 패턴

| 학습 항목 | 학습 목표 |
|----------|----------|
| 2차원 DP | dp[i][j] 형태. Unique Paths, Minimum Path Sum, Edit Distance 패턴을 풀 수 있음. |
| 문자열 DP | Longest Common Subsequence(LCS), Longest Palindromic Substring 패턴을 풀 수 있음. |
| 배낭 문제 (Knapsack) | 0/1 배낭 문제의 점화식(dp[i][w] = max(dp[i-1][w], dp[i-1][w-weight[i]] + value[i]))을 이해하고, 1차원 공간 최적화를 적용 가능. |
| 상태 압축 | 2차원 DP에서 이전 행만 필요한 경우 1차원으로 공간 최적화하는 기법을 적용 가능. |
| 대표 문제 유형 | Unique Paths, Edit Distance, Longest Common Subsequence, Coin Change 2(조합), Word Break 유형을 풀 수 있음. |

### Step 15. Union-Find (서로소 집합)

| 학습 항목 | 학습 목표 |
|----------|----------|
| Union-Find 개념 | 서로소 집합(Disjoint Set)을 효율적으로 관리하는 자료구조. "같은 그룹인가?"(Find) + "두 그룹을 합치기"(Union) 연산을 설명 가능. |
| 기본 구현 | parent 배열 기반 구현. Find(루트 찾기) + Union(루트 연결) 기본 코드를 작성 가능. |
| 경로 압축 (Path Compression) | Find 시 부모를 루트로 직접 연결하여 트리를 평탄화. 시간 복잡도를 거의 O(1)(아커만 역함수 α(n))로 만드는 원리를 설명 가능. |
| 랭크/크기 기반 합치기 (Union by Rank/Size) | 작은 트리를 큰 트리 밑에 붙여 트리 높이를 최소화하는 이유를 설명 가능. |
| 활용 패턴 | 그래프 연결 요소 개수, 사이클 감지(무방향 그래프), 네트워크 연결 판별에 활용 가능. |
| 대표 문제 유형 | Number of Connected Components, Redundant Connection, Number of Provinces, Accounts Merge 유형을 풀 수 있음. |

---

### Step 16. Trie (트라이)

| 학습 항목 | 학습 목표 |
|----------|----------|
| Trie 개념 | 문자열을 문자 단위로 트리에 저장하는 자료구조. 접두사(Prefix) 검색에 O(m)(m=문자열 길이)으로 최적인 이유를 설명 가능. |
| 기본 구현 | TrieNode(children 배열/맵 + isEnd 플래그), insert, search, startsWith 메서드를 구현 가능. |
| HashMap vs Trie | 단순 존재 여부 확인은 HashMap이 유리하지만, 접두사 검색/자동완성은 Trie가 유리한 이유를 설명 가능. |
| 활용 패턴 | 자동완성, 사전 검색, 문자열 필터링, Word Search II(백트래킹 + Trie) 패턴에 활용 가능. |
| 대표 문제 유형 | Implement Trie, Word Search II, Design Add and Search Words Data Structure 유형을 풀 수 있음. |

---

### Step 17. 그리디

| 학습 항목 | 학습 목표 |
|----------|----------|
| 그리디 개념 | 매 순간 최선의 선택이 전체 최적해를 보장하는 경우에 적용. DP와의 차이(그리디: 되돌아가지 않음, DP: 모든 경우 고려)를 설명 가능. |
| 그리디가 최적인지 판단 | "이 문제에 그리디가 통하는가?"를 판단하는 기준(그리디 선택 속성 + 최적 부분 구조)을 설명 가능. 반례를 찾아 그리디가 안 되는 경우를 식별 가능. |
| 정렬 + 그리디 | 정렬 후 순서대로 처리하는 패턴(회의실 배정, Interval 문제). |
| 대표 문제 유형 | Jump Game, Merge Intervals, Non-overlapping Intervals, Task Scheduler 유형을 풀 수 있음. |

### Step 18. 백트래킹

| 학습 항목 | 학습 목표 |
|----------|----------|
| 백트래킹 개념 | 가능한 모든 경우를 탐색하되, 유망하지 않으면 되돌아가는(pruning) 기법을 설명 가능. DFS + 가지치기로 이해 가능. |
| 기본 패턴 | 선택 → 탐색 → 되돌리기(선택 해제)의 3단계를 코드로 구현 가능. |
| 순열/조합/부분집합 | Permutations, Combinations, Subsets를 백트래킹으로 생성 가능. 중복 처리(used 배열 또는 시작 인덱스)를 적용 가능. |
| 대표 문제 유형 | Subsets, Permutations, Combination Sum, N-Queens, Word Search 유형을 풀 수 있음. |

## 3. 자가 검증

### 복잡도 분석
- [ ] 코드를 보고 시간/공간 복잡도를 즉시 판단 가능
- [ ] "이 문제의 입력이 10⁵이면 어떤 복잡도까지 허용되는가?" 즉시 답변 가능

### 자료구조 활용
- [ ] "HashMap으로 O(n)에 풀 수 있는 문제"를 보고 즉시 접근 가능
- [ ] 투 포인터/슬라이딩 윈도우로 O(n²) → O(n) 최적화 가능
- [ ] 단조 스택이 필요한 문제를 식별 가능
- [ ] PriorityQueue로 Top-K 패턴 즉시 적용 가능

### 탐색/그래프
- [ ] BFS vs DFS 선택 기준 설명 가능 (최단 거리 = BFS, 경로 탐색 = DFS)
- [ ] 위상 정렬이 필요한 문제를 식별 가능
- [ ] 다익스트라를 구현하고 "음수 가중치에서 안 되는 이유" 설명 가능
- [ ] Union-Find로 연결 요소/사이클 감지 문제를 풀 수 있음
- [ ] Trie를 구현하고 접두사 검색 문제에 적용 가능

### DP
- [ ] 문제를 보고 "dp[i]의 정의"를 세우고 점화식을 도출 가능
- [ ] 1차원/2차원 DP 문제를 풀고 공간 최적화 적용 가능
- [ ] "이 문제가 DP인지 그리디인지" 판단 가능

### 종합
- [ ] LeetCode Medium 문제를 30~40분 내 풀 수 있음
- [ ] Top Interview 150 중 100문제 이상 풀이 완료
- [ ] 문제를 보고 "어떤 자료구조/알고리즘을 쓸지" 1분 내 판단 가능
