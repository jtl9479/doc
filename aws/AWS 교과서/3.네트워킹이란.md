# 3.1 네트워킹이란

## 3.1.1 네트워킹 정의

네트워킹은 '서로 연결한다.'는 뜻으로 서로 간에 의사소통을 하는 환경입니다.

어떤 IT서비스를 제공하고자 한다면, 그 전에 먼저 다양한 IT자원이 통신할 수 있는 네트워킹 환경이 구성되어야 합니다. 이런 측면에서 네트워킹은 IT영역에서 필수이자 모든 IT 환경의 밑바탕이 되는 초석이라고 볼 수 있습니다.


## 3.1.2 네트워킹 요소

### OSI 7계층

1. 물리 계층 : 네트워크 하드웨어 전송 기술을 이루는 계층, 물리적으로 연결된 매체가 서로 데이터를 송수신할 수 있게 연결하고 유지하는 역할
(100BASE-TX, Wireless 등)
2. 데이터링크 계층 : 물리 계층에서 송수신 되는 정보의 오류와 흐름을 제어 (Ethernet, PPP, MAC, LLC)
3. 네트워크 계층 : 데이터를 목적지까지 전달하는 계층, 최적의 통신 경로를 찾는다. (IP, ICMP, IPsec, ARP)
4. 전송 계층 : 종단의 대상 간의 데이터 전송을 다루는 계층(TCP, UDP)
5. 세션 계층 : 종단의 대상 간 응용 프로세스 통신을 관리하는 방법, 데이터 통신을 위한 논리적인 연결을 담당(SSL, TLS)
6. 표현 계층 : 데이터 형식에 차이가 있을 때 데이터를 서로 이해할 수 있는 형태로 변환하는 역할(JPG, XDR, AFP)
7. 응용 계층 : 응용 프로세스와 직접 연결하여 실제 응용 프로그램을 서비스하는 역할(HTTP, SSH, DNS)

#### 왜 계층으로 나누는가

한 덩어리로 만들면 유선을 Wi-Fi로 바꿀 때 웹 브라우저까지 다시 만들어야 한다. 계층을 나누면 **위아래와의 약속만 지키면 각 층을 따로 갈아 끼울 수 있다.** 실제로 1계층이 유선에서 무선으로 바뀌어도 7계층의 HTTP는 아무것도 바뀌지 않는다.

그래서 장비의 계층도 생김새가 아니라 **"무엇을 보고 판단하느냐"**로 정해진다. MAC 주소를 보면 2계층(스위치), IP 주소를 보면 3계층(라우터), 포트 번호를 보면 4계층(방화벽)이다.

> ❓ 확인 필요: 계층별 **데이터 단위**(비트 / 프레임 / 패킷 / 세그먼트)가 빠져 있다. 계층이 왜 나뉘는지는 이 단위를 봐야 체감된다. 책에 있다면 각 계층 뒤에 덧붙일 것.

### IP주소와 서브넷
#### IP주소
인터넷상에서 IT자원을 식별하는 고유한 주소입니다.
#### 퍼블릭IP주소와 프라이빗IP주소
통신 용도에 따라 분류하며, 퍼블릭 주소는 실제 인터넷에서 사용하려고 인터넷 서비스 공급자에서 제공하는 유일한 공인 IP 주소입니다.
프라이빗 주소는 인터넷이 아닌 독립된 네트워크 내부에서만 사용하려고 네트워크 관리자가 제공하는 사설 IP 주소이다.

##### 언제 어느 쪽을 쓰나

**사용자가 접근하면 퍼블릭, 내 시스템의 다른 구성요소가 접근하면 프라이빗**이다.

| 통신 | 쓰는 주소 |
|------|----------|
| 직원이 브라우저로 ERP 화면 접속 | 웹 서버의 **퍼블릭** IP |
| 웹 서버 → DB 서버 데이터 조회 | DB 서버의 **프라이빗** IP |

프라이빗 주소를 따로 둔 이유는 두 가지다. 퍼블릭 IP는 전 세계에서 유일해야 해서 서버마다 주면 고갈되고, **주소가 없는 서버는 외부에서 도달할 경로 자체가 없어** 안전하다. 그래서 DB 서버에는 퍼블릭 IP를 주지 않는 것이 정석이다.

#### 고정 IP 주소와 유동 IP 주소
고정 IP주소는 네트워크 관리자가 수동으로 할당하는 방식이며, 유동 IP 주소는 특정 서버가 IP 주소 범위에 따라 동적으로 할당하는 방식이다.

유동 IP 주소는 DHCP프로토콜을 통해 주소를 제공하는 서버, 주소를 할당받는 클라이언트로 구성되며, IP 주소를 임대하는 형태를 취한다.

> EC2의 퍼블릭 IP가 중지·시작 때마다 바뀌는 것이 유동 IP다. 고정하려면 Elastic IP가 필요하다. 프라이빗 IP는 바뀌지 않기 때문에 내부 통신은 이쪽을 기준으로 짠다.

 #### 서브넷과 서브넷 마스크  
 네트워크는 하나의 네트워크로만 구성되어 있지 않다.
 주체와 목적에 따라 부분 네트워크로 나뉘고, 서로 연결하여 거대한 네트워크 환경을 이루고 있다. 여기에서 서브넷은 부분 네트워크를 의미하며, 다양한 서브넷이 연결되어 거대한 네트워크 환경을 이룬다고 이해하면 된다. 

 서브넷 마스크는 IP주소와 동일한 32비트 구조에 네트워크 ID와 호스트 ID로 구성되어 있다. 여기에서 네트워크 ID는 서브넷을 구분하는 기준 값이고,
 호스트 ID는 동일 서브넷 내에서 대상을 구분하는 기준 값 입니다.

##### 서브넷 마스크 읽는 법

> ⚠️ 네트워크 ID와 호스트 ID가 **주소에서 어디까지인지**가 없어 이것만으로는 쓸 수 없다. VPC를 만들 때 직접 입력해야 하는 값이라 표기법까지 정리해 둘 것.

`10.0.1.0/24` 에서 `/24`는 **앞 24비트가 네트워크 ID**라는 뜻이다. 32비트 중 24개를 네트워크가 썼으니 남은 8비트가 호스트 자리다.

```
10.0.1.0/24  →  10.0.1. 까지 고정(네트워크) / 마지막 칸만 변함(호스트)

10.0.1.5 와 10.0.1.9   같은 서브넷  → 스위치가 바로 배달
10.0.2.5               다른 서브넷  → 라우터를 거쳐야 함
```

숫자가 작을수록(`/16`) 넓은 네트워크, 클수록(`/28`) 좁은 네트워크다.

 #### 라우팅과 라우터 

라우팅은 네트워킹 통신을 수행할 때 목적지 경로를 선택하는 작업을 의미하며,
이를 수행하는 장비를 라우터라고 한다.
라우터는 라우팅 테이블이라는 서브넷의 경로 리스트를 가지고 목적지 네트워크에 대한 최적 경로를 선택해서 전달하는 역할을 합니다. 

라우터는 **IP 주소를 보고 판단하므로 3계층 장비**다. 같은 서브넷 안의 배달은 MAC 주소를 보는 2계층 스위치가 맡고, 서브넷을 넘어갈 때만 라우터가 나선다.

AWS에는 물리 라우터가 없고 **라우팅 테이블**이 그 역할을 한다.

```
10.0.0.0/16  →  local      (우리 VPC 안이면 내부로)
0.0.0.0/0    →  igw-xxxx   (그 외 전부는 인터넷 게이트웨이로)
```

퍼블릭 서브넷과 프라이빗 서브넷의 차이도 결국 `0.0.0.0/0`이 무엇을 가리키느냐다. 서브넷 자체에 "퍼블릭"이라는 속성이 있는 것이 아니다.

#### TCP/UDP
TCP는 송수신 대상 간 연결을 맺고 데이터 전송 여부를
하나씩 확인하며 전송하는 연결형 프로토콜로, 신뢰성 있는 데이터 전송 보장
UDP는 반대로 송수신 대상 간 연결 없이 전달하는 비연결형 프로토콜이다. 연결이나 제어를 위한 작업이 없어 신뢰성 있는 전송을 보장할 수는 없지만, 빠르게 데이터를 전송할 수 있다.
포트번호는 TCP와 UDP를 사용하는 응용 서비스는 서로 구분할 수 있도록 포트 번호를 사용한다. 이런 포트 번호는 IANA라는 인터넷 할당 번호 관리 기관에서 정의합니다.

**판단 기준은 "빠뜨리면 안 되는가"다.** 결제·파일 전송처럼 하나라도 빠지면 안 되는 것은 TCP, 영상 통화·게임처럼 늦게 오느니 차라리 빠뜨리는 게 나은 것은 UDP다.

### ⚠️ 3.1 오해

- **계층은 장비의 생김새가 아니라 "무엇을 보고 판단하느냐"로 정해진다** — IP를 보면 3계층
- **프라이빗 IP는 회사마다 겹쳐도 된다** — 인터넷으로 내보내지 않기로 약속한 대역이라 부딪히지 않는다
- **퍼블릭 서브넷은 서브넷 자체의 속성이 아니다** — 라우팅 테이블이 인터넷 게이트웨이를 가리키느냐의 차이일 뿐
- **EC2 안에서는 자기 퍼블릭 IP가 보이지 않는다** — `ip addr` 에는 프라이빗 IP만 나온다
