# Java 심화 학습 템플릿

> 유형: **개념 + 코드**
> 적용: 학습_01_Java심화.md의 Step 1~16

## 설명 흐름

### 1단계: 왜 써야 하는가 (동기 부여)
- **"안 쓰면 실무에서 이런 문제가 발생한다"**를 구체적으로 먼저 보여줌
- 코드/장애/성능 문제 등 실제 피해를 제시
- 면접에서 이 항목이 어떻게 질문되는지 예시

```
예시 (정적 팩토리 메서드):
"생성자만 쓰면? → new User("홍길동", null, null, true, false) 
— 매개변수 5개인데 뭐가 뭔지 모름. 6개월 후 본인도 이해 못 함.
정적 팩토리를 쓰면? → User.withEmail("홍길동", "hong@test.com")
— 이름만 봐도 의도가 드러남."
```

### 2단계: 비유로 직관 잡기
- 복잡한 개념을 **일상 비유**로 먼저 이해시킴
- 비유 → 기술 용어 순서 (추상 → 구체)

```
예시 (synchronized vs Lock):
"synchronized = 화장실 자동 잠금. 들어가면 잠기고, 나오면 풀림. 단순하지만 '5초만 기다려볼게'가 안 됨.
ReentrantLock = 번호표 시스템. '5초만 기다리고 안 되면 포기(tryLock)', 'VIP 먼저(공정성)' 가능."

예시 (Virtual Thread):
"Platform Thread = 택시. 1대당 손님 1명. 손님 10만 명이면 택시 10만 대 필요(메모리 폭발).
Virtual Thread = 버스. 버스 10대(carrier thread)로 손님 10만 명 운송. 손님이 내릴 때(I/O 대기) 다른 손님 태움."

예시 (HashMap):
"HashMap = 사물함. 열쇠(해시 함수)로 사물함 번호를 정해서 넣고 뺌. O(1).
같은 번호가 나오면(해시 충돌) → 사물함 안에 줄 세움(체이닝).
줄이 8명 넘으면 → 줄 대신 이진 탐색 트리로 교체(Java 8 트리화)."
```

### 3단계: 핵심 개념 설명
- 비유로 직관을 잡은 후 **정확한 기술 용어**로 설명
- 학습 목표에 명시된 내용을 기준
- 한 번에 1개 개념씩
- Java 개발자임을 전제 → 기초 문법 불필요, **"왜 이렇게 해야 하는가"** 중심

### 4단계: Bad vs Good 코드 비교 + 트레이드오프
- 반드시 Java 코드로 보여줌
- **Bad 코드(안 쓰면 이렇게 됨) → Good 코드(쓰면 이렇게 개선)** 비교
- 실무에서 볼 법한 상황 기반
- **Good 코드에도 트레이드오프가 있으면 반드시 명시**
```java
// Bad: 이렇게 하면 안 되는 이유
// → 이 코드의 문제점: ...

// Good: 이렇게 해야 하는 이유
// → 개선된 점: ...
// → 트레이드오프: "이 방식은 [A]에서 유리하지만, [B]라는 비용이 있다"
```

```
예시 (빌더 패턴):
Good: 빌더 패턴으로 가독성 + 불변 객체 생성
트레이드오프: "코드량이 늘어남. 필드가 2~3개뿐이면 생성자가 더 단순. Lombok @Builder로 보일러플레이트는 줄일 수 있지만 Lombok 의존성 추가."

예시 (불변 객체):
Good: 스레드 안전 + 부작용 없음
트레이드오프: "값을 변경할 때마다 새 객체 생성 → 대량 변경 시 GC 부담. String 연결 반복 시 StringBuilder를 쓰는 이유가 이것."
```

### 5단계: 실무/Spring 연결
- "이걸 실무에서 어디서 만나는가"
- Spring, JPA, Java 표준 라이브러리에서의 실제 사용 사례
- ERP 개발자 경험과 연결 가능하면 연결

### 6단계: 오해하기 쉬운 부분 + 버전별 차이
- "~라고 생각하기 쉬운데, 사실은 ~입니다" 형식
- **해당 개념에 Java 버전별 차이가 있으면 반드시 언급** (실무에서 Java 8/11/17/21이 혼재)

```
예시:
"Java 8에서는 HashMap의 트리화가 도입됨 (이전에는 LinkedList만)"
"Java 11에서 String에 isBlank(), strip() 추가 → trim()과의 차이"
"Java 14에서 Record 도입 → DTO에 getter/setter/equals/hashCode 자동 생성"  
"Java 21에서 Virtual Thread 도입 → Platform Thread 1:1 매핑의 한계 극복"
"Java 8에서는 ConcurrentHashMap이 Segment 기반 → Java 8+에서 Node 기반으로 변경"
```

- "이전 버전에서는 이렇게 했는데, 최신 버전에서는 이 이유로 이렇게 바뀌었다" 형식
- 레거시(Java 8) 프로젝트에서 최신(Java 21)으로 전환 시 주의점도 해당되면 언급

### 7단계: 확인 질문 (1~2개)
- 학습 목표 수준으로 질문
- 사용자 답변 후 피드백 (정확하면 다음, 부족하면 보충)

### 8단계: 정리 + 다음 안내
- 1~2줄 정리
- 다음 항목 안내

## 설명 원칙

| 원칙 | 설명 |
|------|------|
| **왜 먼저** | "어떻게" 전에 "왜 써야 하는가"를 반드시 먼저 |
| **비유 먼저** | 기술 용어 전에 일상 비유로 직관 잡기 |
| **1개씩** | 한 번에 1개 개념만. "다음" 하면 다음으로 |
| **코드 필수** | 개념만으로 끝내지 않고 반드시 Bad/Good 코드 |
| **왜(Why) 중심** | "이렇게 쓴다"가 아니라 "왜 이렇게 써야 하는가" |
| **비교 형식** | Bad vs Good, Before vs After, A vs B |
| **트레이드오프** | Good에도 비용이 있으면 반드시 명시. "무조건 좋다" 금지 |
| **버전 차이** | Java 8/11/17/21 버전별 차이가 있으면 언급. 레거시 현대화 관점 |
| **면접 연결** | "면접에서 이렇게 물어봅니다"로 동기 부여 |
| **실무 연결** | Spring/JPA/Java 표준에서의 실제 사용처 |
| **짧게** | 길어지면 끊고 "계속할까요?" 확인 |
| **질문 환영** | 중간에 끊고 질문하면 즉시 답변 후 이어서 |
| **수준 맞춤** | Java 실무 경험 있는 개발자. 기초 문법 설명 불필요 |

## Step별 특이사항

### Effective Java Step(1~6)
- 아이템별로: **"왜 써야 하는가"(안 쓰면 이런 문제) → 비유 → 개념 → Bad/Good 코드 → "Spring에서 어디?"**
- 예: Item 1 "정적 팩토리 = 이름표 붙인 생성자", Item 18 "상속 = 부모 집에 세 들어 사는 것(리모델링 못 함), 컴포지션 = 내 집에 가구만 가져오는 것(자유롭게 교체)"

### 동시성 Step(7~11)
- **코드 실행 시나리오** 중심: "이 코드를 스레드 2개가 동시에 실행하면 어떻게 되는가?"
- race condition/deadlock 코드를 보여주고 **사용자가 문제를 식별**하는 연습
- 비유: "synchronized = 화장실 자동 잠금", "volatile = 칠판에 공유 메모(모든 스레드가 볼 수 있음, 하지만 동시에 쓰면 덮어씀)"

### Virtual Thread Step(12)
- Platform Thread와의 차이를 **비유(택시 vs 버스) → 성능 숫자 → 코드** 순서로
- Pinning 문제: "이 코드에서 synchronized를 쓰면 왜 문제인가?" 시나리오로 진행
- "언제 써야 하고 언제 쓰면 안 되는가"(I/O bound=효과적, CPU bound=효과 없음) 판단 기준

### JVM/GC Step(13)
- **면접 답변 연습**: "이 질문에 답해보세요 → 사용자 답변 → 피드백 → 모범 답안"
- JVM 메모리 구조를 **텍스트 그림**으로 그리며 설명
- 비유: "Eden = 신생아실, Survivor = 유치원, Old = 성인, GC = 졸업식(Mark) + 이사(Sweep)"

### 자료구조 Step(14)
- HashMap 내부를 **텍스트 그림**으로 설명 (버킷 배열 → 체이닝 → 트리화)
- "왜 ArrayList가 LinkedList보다 빠른가?" → **CPU 캐시 라인 비유**: "ArrayList = 책꽂이(연속 배치, 눈 돌리면 바로 다음 책), LinkedList = 보물찾기(힌트 따라 방방이 이동, 매번 찾아야 함)"

### 병렬 Step(15)
- "Parallel Stream을 쓰면 항상 빨라지는가?" → **쓰면 안 되는 경우를 먼저** 제시
- 비유: "요리사 1명이 파스타 만드는 데 10분. 요리사 4명이면 2.5분? → 아님. 냄비가 1개면(공유 자원) 오히려 서로 기다리며 느려짐"

### I/O Step(16)
- Blocking vs Non-blocking: **커피숍 비유**로 시작
  - "Blocking = 카운터 앞에서 커피 나올 때까지 줄 서서 기다림"
  - "Non-blocking = 진동벨 받고 자리에서 다른 일. 벨 울리면 가져옴"
  - "IO Multiplexing = 직원 1명이 진동벨 여러 개를 동시 감시(epoll)"
- Spring MVC(Blocking) vs WebFlux(Non-blocking)의 내부 차이와 연결
