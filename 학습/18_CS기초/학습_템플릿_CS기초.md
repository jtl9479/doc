### 비유 예시
```
프로세스 = "독립된 집. 각자 주방/거실/침실(메모리) 보유. 이웃과 벽(격리)으로 분리"
스레드 = "한 집 안의 가족. 주방/거실(Heap)은 공유, 방(Stack)만 각자"
컨텍스트 스위칭 = "책 2권 번갈아 읽기. 바꿀 때마다 '어디까지 읽었지?' 기억해야 함(오버헤드)"
가상 메모리 = "도서관 자리 예약. 자리(물리 메모리)가 없어도 예약번호(가상 주소)는 줄 수 있음. 실제로 앉을 때(접근) 자리가 없으면 다른 사람을 옮김(페이지 교체)"
페이지 캐시 = "자주 빌리는 책을 카운터(메모리)에 미리 꺼내둠. 서고(디스크)에 갈 필요 없음"
Blocking IO = "카운터 앞에서 커피 나올 때까지 줄 서서 기다림"
Non-blocking IO = "진동벨 받고 자리에서 다른 일. 벨 울리면 가져옴"
IO Multiplexing = "직원 1명이 진동벨 여러 개를 동시 감시(epoll)"
TCP = "전화. 연결 확인(3-way) → 통화 → 종료 확인(4-way). 순서 보장, 재전송"
UDP = "편지. 보내고 끝. 도착 확인 안 함. 빠르지만 유실 가능"
Strategy 패턴 = "계산기의 연산 버튼 교체. +/-/× 버튼을 갈아끼움. 계산기 자체는 안 바꿈"
Proxy 패턴 = "대리인. 사장님(실제 객체) 대신 비서(프록시)가 전화 받아서 스케줄 확인 후 연결"
상속 vs 조합 = "상속 = 부모 집에 세 들어 사는 것(리모델링 못 함). 조합 = 내 집에 가구만 가져오는 것(자유롭게 교체)"
```

### 트레이드오프 예시
```
프로세스: 안정성↑(격리) ↔ 생성 비용↑ 통신 비용↑(IPC)
스레드: 생성 비용↓ 통신 쉬움 ↔ 안정성↓(하나 죽으면 전체 영향) + 동기화 필요
Blocking IO: 구현 단순 ↔ 스레드 낭비(동시 1000연결 = 1000스레드)
Non-blocking IO: 적은 스레드로 다수 연결 ↔ 코드 복잡(콜백/이벤트)
TCP: 신뢰성↑ ↔ 속도↓(핸드셰이크, 재전송)
UDP: 속도↑ ↔ 신뢰성↓(유실, 순서 미보장)
Strategy: 유연↑(알고리즘 교체) ↔ 클래스 수↑
Singleton: 인스턴스 1개(메모리↓) ↔ 전역 상태 위험, 테스트 어려움
```

## 설명 흐름

### 개념 Step (1~6): 면접 Q&A 모드
1. **면접 질문으로 시작**: "프로세스와 스레드의 차이를 설명해보세요"
2. **사용자 답변** (먼저 답변)
3. **비유로 보충**: "프로세스 = 독립된 집, 스레드 = 한 집 가족"
4. **정확한 기술 설명 + 트레이드오프**
5. **오해하기 쉬운 부분**:
```
"프로세스가 스레드보다 안전하니까 항상 프로세스를 쓴다" → 프로세스 생성 비용↑ 통신 비용↑. 대부분 스레드 사용
"Non-blocking이 항상 좋다" → 코드 복잡↑. 단순한 경우 Blocking이 더 적합
"TCP가 UDP보다 항상 좋다" → 실시간 스트리밍/게임에서는 UDP가 적합(속도 우선)
"컨텍스트 스위칭은 나쁘다" → 멀티태스킹에 필수. 비용을 줄이는 것이 목표(경량 스레드/Virtual Thread)
"LRU가 최고의 페이지 교체 알고리즘" → LRU는 근사. 최적(OPT)은 미래를 알아야 해서 이론적
"디자인 패턴을 외워야 한다" → 외우는 게 아니라 "이 문제에 이 패턴이 적합한가" 판단이 핵심
```
6. **"30초 답변" + "2분 상세 답변"** 두 버전 제시
7. **확인 질문**: 면접 형태로 즉시 답변 연습
```
Step 1: "프로세스와 스레드의 차이를 설명해보세요"
Step 2: "가상 메모리란? 페이지 폴트란?"
Step 4: "동기/비동기 vs Blocking/Non-blocking 차이를 2x2 매트릭스로 설명해보세요"
Step 5: "IO Multiplexing이란? epoll은 왜 select보다 효율적인가?"
Step 6: "TCP 3-way Handshake 과정을 설명해보세요"
Step 7: "Strategy 패턴을 Spring에서 어디에 쓰는가?"
```
8. **실무 연결**: "이게 Java/Spring/Kafka에서 어떻게?"

### 면접 총정리 Step (7): 빠른 Q&A
- Claude가 질문 → 사용자 즉시 답변 → 피드백 → 다음 질문
- 빠른 템포 (1문제 1~2분)
