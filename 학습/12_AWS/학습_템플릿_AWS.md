# AWS 학습 템플릿

> 유형: **개념 + 서비스별 구성 + 아키텍처 패턴**
> 적용: 학습_12_AWS.md의 Step 1~14

## 공통 원칙

| 원칙 | 설명 |
|------|------|
| **왜 먼저** | "온프레미스로 이것을 하려면 이렇게 힘든데, AWS를 쓰면 이렇게 간단" |
| **비유 먼저** | 클라우드/서비스를 일상 비유로 직관 잡기 |
| **트레이드오프** | 모든 서비스 선택에 비용(돈) + 기술 트레이드오프 명시 |

### 비유 예시
```
클라우드 = "렌터카. 차(서버)를 사지 않고 빌려 씀. 쓴 만큼 비용. 필요 없으면 반납"
EC2 = "렌터카 자체. 원하는 크기(인스턴스 유형) 선택"
S3 = "무제한 창고. 짐(파일)을 넣고 빼기만 하면 됨. 창고 용량 걱정 없음"
RDS = "관리형 주차장. 주차(DB 운영)를 대행. 세차(패치), 보험(백업) 포함"
Lambda = "택시. 탈 때만 비용. 기사(서버)를 고용할 필요 없음. 단, 장거리(15분 초과)는 불가"
VPC = "울타리 친 사유지. 내 땅(네트워크) 안에서 건물(서버)을 배치"
IAM = "출입증 시스템. 누가 어디에 들어갈 수 있는지 관리"
ELB = "호텔 로비 안내원. 손님(요청)을 빈 방(서버)으로 분배"
Auto Scaling = "성수기 아르바이트 채용. 바쁘면 추가, 한가하면 감축"
```

### 트레이드오프 예시
```
On-Demand: 유연(언제든 시작/중지) ↔ 시간당 비용 최고
Reserved: 비용↓(최대 72% 할인) ↔ 1~3년 약정, 유연성↓
Spot: 비용↓(최대 90%) ↔ 언제든 중단 가능
Fargate: 서버리스(관리 불필요) ↔ EC2 모드 대비 비용↑
ECS: AWS 통합 간편 ↔ AWS 종속(Lock-in)
EKS: K8s 표준, 이식성 ↔ 복잡, 비용↑
Lambda: 서버 관리 X ↔ 콜드 스타트, 15분 제한, 상태 없음
```

## 설명 흐름
1. **왜 써야 하는가**: "온프레미스로 하면 이렇게 힘든데, 이 서비스를 쓰면"
2. **비유로 직관 잡기**: 온프레미스 대응물과 비교
3. **핵심 개념 + 과금 모델**
4. **콘솔/CLI 가이드** + 아키텍처 다이어그램
5. **비용 + 트레이드오프**: "이 설정에서 월 얼마, 대안은?"
6. **오해하기 쉬운 부분**:
```
"프리 티어 = 무료" → 한도 초과 시 과금. EBS, Elastic IP, NAT Gateway는 프리 티어에 포함 안 됨
"클라우드는 항상 싸다" → 설정 방치하면 온프레미스보다 비쌀 수 있음. Reserved/Spot 활용 필요
"EC2 = 서버 1대" → EC2 인스턴스는 재시작 시 IP 변경(Elastic IP 필요), 디스크는 별도(EBS)
"RDS Multi-AZ = 읽기 성능 향상" → Multi-AZ는 HA(고가용성). 읽기 분산은 Read Replica
"Lambda는 모든 것에 적합" → 15분 제한, 콜드 스타트, 상태 없음. 장시간/상태 유지는 EC2/ECS
"ECS와 EKS 중 EKS가 항상 좋다" → EKS는 복잡+비용↑. AWS에 올인하면 ECS가 더 단순
```
7. **확인 질문**: 사용자 답변 → 피드백
```
Step 3: "IAM 사용자와 역할(Role)의 차이는?"
Step 4: "VPC 3-Tier 구조를 그려보세요"
Step 5: "On-Demand vs Reserved vs Spot 차이와 선택 기준은?"
Step 8: "RDS Multi-AZ vs Read Replica 차이는?"
Step 9: "ECS Fargate vs EC2 모드 차이는?"
Step 14: "이 시스템을 AWS로 구성하면 어떤 서비스를 쓰겠는가?"
```
8. **프리 티어 주의사항**
9. **정리 + 다음 안내**

## Step별 특이사항
- 기초 Step(1~3): 프리 티어 한도 + Billing Alert 필수 강조
- VPC Step(4): 3-Tier 구조 그림이 핵심
- EC2 Step(5~6): 인스턴스 유형 + 과금 모델(On-Demand/Reserved/Spot) 비교
- 컨테이너 Step(9~10): ECS vs EKS 트레이드오프 + K8s 학습 연계
- Lambda Step(11): Java 콜드 스타트 문제 + 대응
- 아키텍처 Step(14): "이 시스템을 AWS로 구성하라" → 사용자 설계 → 리뷰
