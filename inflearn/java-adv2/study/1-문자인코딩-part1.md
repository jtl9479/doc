## 1. 컴퓨터와 데이터

> **TL;DR**
> - 컴퓨터 메모리는 트랜지스터(전구)로 구성되어 0과 1만 표현 가능
> - 모든 데이터는 궁극적으로 2진수(0과 1)로 저장됨
> - 바이너리 데이터와 텍스트 데이터 두 종류가 있음

### 핵심 개념

개발자가 다루는 데이터는 크게 두 가지입니다:
- **바이너리 데이터**: 010101로 되어 있는 byte 기반 데이터
- **텍스트 데이터**: "ABC", "가나다"와 같은 문자 데이터

### 상세 설명

컴퓨터의 메모리는 **반도체**로 만들어져 있습니다. 이것은 쉽게 말해 수많은 **전구(트랜지스터)**들이 모여있는 것입니다.

```
┌─────────────────────────────────────┐
│              메모리                  │
│  💡💡💡💡💡💡💡💡                    │
│  (트랜지스터 = 전자 스위치)           │
│                                      │
│  전기 흐름 O = 1                     │
│  전기 흐름 X = 0                     │
└─────────────────────────────────────┘
```

각 트랜지스터는 **두 가지 상태**만 가질 수 있습니다:
- 전기가 흐르는 상태 → `1`
- 전기가 흐르지 않는 상태 → `0`

### 주요 포인트

- 컴퓨터는 10진수를 직접 이해하지 못함
- 모든 데이터는 0과 1의 조합으로 저장됨
- 현대 컴퓨터 메모리는 초당 수십억 번의 데이터 접근 처리 가능

## 2. 2진수와 비트

> **TL;DR**
> - 1bit = 2가지 표현 (0, 1)
> - 8bit = 1byte = 256가지 표현 (0~255)
> - bit가 늘어날수록 표현 가능한 값이 2배씩 증가

### 핵심 개념

**비트(bit)**: 2가지만 표현할 수 있는 최소 단위

| bit 수 | 표현 가능 개수 | 범위 |
|--------|--------------|------|
| 1bit | 2 | 0 ~ 1 |
| 2bit | 4 | 0 ~ 3 |
| 3bit | 8 | 0 ~ 7 |
| 4bit | 16 | 0 ~ 15 |
| 7bit | 128 | 0 ~ 127 |
| **8bit (1byte)** | **256** | **0 ~ 255** |

### 상세 설명

#### 전구 1개 (1bit) - 2가지 표현
```
[OFF] = 0
[ON]  = 1
```

#### 전구 2개 (2bit) - 4가지 표현
```
[OFF][OFF] = 00 = 0
[OFF][ON]  = 01 = 1
[ON][OFF]  = 10 = 2
[ON][ON]   = 11 = 3
```

#### 숫자 저장 예시
10진수 `100`을 메모리에 저장한다면?
→ 컴퓨터는 2진수 `1100100`으로 변환해서 저장

### 음수 표현

8bit로 음수를 표현해야 하는 경우:
- 첫 번째 bit: 부호 비트 (0=양수, 1=음수)
- 나머지 7bit: 숫자 표현

```
양수만: 0 ~ 255 (256가지)
음수포함: -128 ~ 127 (256가지)
```

### 주요 포인트

- **8bit = 1byte**는 컴퓨터에서 가장 기본적인 데이터 단위
- Java의 `byte` 타입: -128 ~ 127 범위

## 3. 문자 인코딩의 필요성

> **TL;DR**
> - 문자 'A'를 2진수로 변환하는 수학 공식은 없음
> - **문자 집합(Character Set)**: 문자와 숫자를 매핑한 표
> - **인코딩**: 문자 → 숫자, **디코딩**: 숫자 → 문자

### 핵심 개념

10진수는 수학 공식으로 2진수로 변환 가능합니다. 하지만 **문자 'A', 'B'를 2진수로 변경하는 수학 공식은 존재하지 않습니다.**

해결책: **문자 집합(Character Set)** 만들기!

### 상세 설명

```
┌──────────────────────────────────────────────────────┐
│                문자 집합(Character Set)               │
├────────┬────────┐                                    │
│  문자  │  숫자  │                                    │
├────────┼────────┤         ┌───┐                      │
│   A    │   65   │   A ───▶│   │───▶ 65              │
│   B    │   66   │  저장    │표 │    숫자 조회         │
│   a    │   97   │         └───┘                      │
│   b    │   98   │                                    │
└────────┴────────┴────────────────────────────────────┘
```

### 문자 인코딩과 디코딩

| 용어 | 설명 | 예시 |
|------|------|------|
| **문자 인코딩** | 문자 → 숫자 변환 | 'A' → 65 |
| **문자 디코딩** | 숫자 → 문자 변환 | 65 → 'A' |

### 주요 포인트

- 인코딩과 디코딩에는 **같은 문자 집합**을 사용해야 함
- 다른 문자 집합을 사용하면 **문자가 깨짐**

## 4. ASCII 문자 집합

> **TL;DR**
> - 1960년대 개발된 최초의 표준 문자 집합
> - 7bit 사용 → 128가지 문자 표현
> - 영문 알파벳, 숫자, 특수문자, 제어문자 포함

### 핵심 개념

**ASCII** (American Standard Code for Information Interchange)
- 1960년대 개발
- **7bit** 사용 → 총 **128가지** 문자 표현
- 영문, 숫자, 키보드 특수문자, 제어문자 포함

### 상세 설명

#### 제어 문자 (0-31, 127)
| 십진수 | 문자 | 설명 |
|--------|------|------|
| 0 | NUL | Null 문자 |
| 10 | LF | Line Feed (줄바꿈) |
| 13 | CR | Carriage Return |
| 27 | ESC | Escape |
| 127 | DEL | 삭제 |

#### 출력 가능한 문자 (32-126)
| 십진수 | 문자 | 설명 |
|--------|------|------|
| 32 | (공백) | 스페이스 |
| 48-57 | 0-9 | 숫자 |
| 65-90 | A-Z | 대문자 |
| 97-122 | a-z | 소문자 |

### 주요 포인트

- 'A' = 65, 'a' = 97, '0' = 48
- ASCII의 숫자(0-9)는 **문자로 표현된 숫자** (그림과 같은 것)
- Java의 `String "123"`에 들어있는 것이 ASCII 숫자

### 주의사항

```java
// ASCII 숫자는 10진수 계산에 사용할 수 없음
char c = '1';       // ASCII 코드 49
int n = 1;          // 정수 1
// c + n = 50 (문자 '2'의 ASCII 코드)
```

## 5. ISO-8859-1 (LATIN-1)

> **TL;DR**
> - ASCII 확장판 (서유럽 문자 추가)
> - 8bit(1byte) 사용 → 256가지 표현
> - ASCII(0-127) 완벽 호환 + 서유럽 문자(128-255)

### 핵심 개념

**ISO-8859-1** (= LATIN1 = ISO-LATIN-1)
- 1980년대 개발
- 국제 표준화 기구(ISO)에서 제정
- **8bit(1byte)** 사용 → **256가지** 표현

### 상세 설명

```
┌─────────────────────────────────────┐
│           ISO-8859-1               │
├─────────────────────────────────────┤
│  0 - 127  : ASCII (영문, 숫자 등)   │
│  128 - 255: 서유럽 문자 추가        │
│             À, Á, Â, Ã, Ä, Å 등    │
└─────────────────────────────────────┘
```

### 주요 포인트

- ASCII와 **완벽하게 호환**
- 영문 1byte, 서유럽 확장 문자 1byte
- **한글 표현 불가능**

## 6. 한글 문자 집합 (EUC-KR, MS949)

> **TL;DR**
> - EUC-KR: 자주 사용하는 한글 2,350자만 포함 (1980년대)
> - MS949: EUC-KR 확장, 모든 한글 11,172자 포함 (1990년대)
> - 둘 다 ASCII 호환, 한글은 2byte 사용

### 핵심 개념

한글의 글자 수가 많아 **1byte(256가지)로는 표현 불가능** → **2byte(65,536가지)** 필요

### EUC-KR

| 항목 | 내용 |
|------|------|
| 개발 시기 | 1980년대 |
| 특징 | 자주 사용하는 한글 **2,350자**만 포함 |
| 구성 | ASCII + 한글 2,350자 + 한자 4,888자 |
| 영문 | 1byte |
| 한글 | 2byte |
| ASCII 호환 | O |

### MS949

| 항목 | 내용 |
|------|------|
| 개발 시기 | 1990년대 (마이크로소프트) |
| 특징 | 모든 한글 **11,172자** 포함 |
| 구성 | EUC-KR 확장 |
| 영문 | 1byte |
| 한글 | 2byte |
| EUC-KR 호환 | O (상위 호환) |

### 상세 설명

#### EUC-KR의 한계
```
한글 조합 가능한 글자 수:
- 초성 19개 × 중성 21개 × 종성 28개 = 11,172자

EUC-KR은 2,350자만 포함:
- "가", "나", "다" → O (자주 사용)
- "뷁", "쀍", "삡" → X (표현 불가)
```

#### MS949의 해결
```
EUC-KR을 확장하여 모든 한글 11,172자 수용
- EUC-KR과 호환 유지
- 윈도우 시스템에서 계속 사용됨
```

### 주요 포인트

- EUC-KR로 인코딩한 "가"는 MS949로 디코딩 가능 (호환)
- MS949로 인코딩한 "뷁"은 EUC-KR로 디코딩 불가능 (문자 집합에 없음)
- 한글 윈도우의 기본 인코딩은 **MS949**

### 주의사항

```
EUC-KR로 "뷁" 인코딩 시도:
→ 문자 집합에 없음 → 숫자 63으로 인코딩 → '?' 출력
```

## 정리

| 문자 집합 | bit/byte | 표현 가능 | ASCII 호환 | 한글 지원 |
|-----------|----------|----------|-----------|----------|
| ASCII | 7bit | 128자 | - | X |
| ISO-8859-1 | 8bit(1byte) | 256자 | O | X |
| EUC-KR | 가변(1-2byte) | 2,350자 | O | O (일부) |
| MS949 | 가변(1-2byte) | 11,172자 | O | O (전체) |
