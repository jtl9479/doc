# 보안 학습 템플릿

> 유형: **공격/방어 시나리오 + 코드 리뷰**
> 적용: 학습_15_보안.md의 Step 1~11

## 공통 원칙

| 원칙 | 설명 |
|------|------|
| **왜 먼저** | "이 보안을 안 하면 이런 공격으로 이런 피해가 발생한다" (실제 사고 사례) |
| **비유 먼저** | 보안 개념을 일상 비유로 직관 잡기 |
| **트레이드오프** | 보안 강화에도 비용(성능, 사용성, 개발 공수)이 있음 |

### 비유 예시
```
HTTPS = "밀봉 편지. 평문(HTTP)은 엽서(누구나 읽음). HTTPS는 밀봉(암호화)해서 수신자만 열람"
SQL Injection = "은행 창구에서 '100만원 출금' 적는 칸에 '100만원 출금 그리고 모든 계좌 조회'를 적는 것"
XSS = "게시판에 '읽으면 자동 실행되는 쪽지'를 올림. 다른 사용자가 읽으면 쿠키 탈취"
CSRF = "내 명의로 된 위조 서류를 내가 모르게 제출. 내가 로그인한 상태를 악용"
JWT = "놀이공원 입장 팔찌. 한번 차면(발급) 놀이기구마다 보여주면 됨(서버 조회 불필요). 잃어버리면(탈취) 다른 사람이 쓸 수 있고, 만료 전까지 취소 어려움"
OAuth2 = "대리 운전. 차 키(비밀번호)를 주는 게 아니라, '운전만 가능한 임시 권한(Access Token)'을 줌"
시크릿 하드코딩 = "열쇠를 현관 화분 밑에 숨기는 것. 한 명이라도 알면 끝"
```

### 트레이드오프 예시
```
HTTPS: 보안↑ ↔ 암/복호화 CPU 오버헤드 (현대 하드웨어에서는 미미)
JWT: 무상태(확장성↑) ↔ 즉시 무효화 어려움
JWT + Redis 블랙리스트: 즉시 무효화 ↔ 무상태 원칙 일부 포기
세션: 즉시 무효화 ↔ 서버 상태 유지, 수평 확장 시 세션 공유 필요
MFA: 보안↑ ↔ 사용자 불편↑
강한 비밀번호 정책: 보안↑ ↔ 사용자 이탈 위험
ACL (Redis): 보안↑ ↔ 설정 복잡성↑
```

## 설명 흐름

### OWASP/개념 Step: 공격 → 방어
1. **왜 알아야 하는가**: 실제 사고 사례 제시
2. **비유로 공격 직관 잡기**
3. **공격 시나리오** (구체적 공격 코드/요청)
4. **"이 코드에 취약점이 있는가?"** → 사용자 참여 → 피드백
5. **방어법 + 안전한 코드 + 트레이드오프**
6. **오해하기 쉬운 부분**:
```
"HTTPS면 완전히 안전하다" → 전송은 암호화되지만 서버 측 취약점(SQL Injection 등)은 별개
"JWT가 세션보다 안전하다" → JWT 탈취 시 즉시 무효화 어려움. 세션은 서버에서 즉시 삭제 가능
"CSRF 토큰은 항상 필요하다" → JWT(Stateless)에서는 CSRF 불필요(쿠키 안 쓰면)
"bcrypt로 해싱하면 절대 못 풀다" → 레인보우 테이블은 막지만 GPU 무차별 대입은 시간 문제. 강한 비밀번호 + MFA 병행
"OAuth2를 쓰면 인증이 완료된다" → OAuth2는 인가(Authorization). 인증은 OIDC가 해결
"소스 코드가 비공개면 시크릿 안전" → Git 이력에 남아있거나, 퇴사자가 가져갈 수 있음
```
7. **확인 질문**: 사용자 답변 → 피드백
```
Step 3: "SQL Injection 공격 원리와 PreparedStatement 방어를 설명해보세요"
Step 5: "세션 vs JWT 차이와 선택 기준은?"
Step 6: "JWT를 즉시 무효화하기 어려운 이유와 대응은?"
Step 7: "OAuth2 Authorization Code Grant 흐름을 설명해보세요"
Step 9: "Docker 이미지를 non-root로 실행해야 하는 이유는?"
Step 11: "이 코드의 보안 취약점을 찾아보세요" (코드 제시)
```

### 인증/시크릿 Step: 흐름도 + 코드
1. **왜 써야 하는가**: "안 쓰면 이런 보안 사고"
2. **비유로 직관 잡기**
3. **전체 흐름 다이어그램** (JWT 발급→검증→갱신)
4. **코드 예제 + 트레이드오프** (JWT vs 세션, AT+RT 전략)
5. **보안 시나리오**: "JWT 탈취되면?" "RT 유출되면?"

### 코드 리뷰 Step: 취약점 식별
- Claude가 코드 제시 → 사용자가 취약점 식별 → 피드백

## Step별 특이사항
- OWASP Step(3~4): 공격 시나리오 → 취약 코드 → 안전 코드 흐름. MyBatis ${} → #{} 연결
- JWT Step(6): RT Rotation + Redis 블랙리스트 트레이드오프
- OAuth2 Step(7): 전체 흐름 다이어그램이 핵심
- 인프라 보안 Step(9): Docker/K8s/AWS 보안 → 타 학습 연계
- 실전 Step(11): 개인정보 암호화 + 감사 로그 (ERP 도메인)
