# NoSQL 학습 템플릿

> 유형: **개념 + 명령어 실습 + DB 선택 판단**
> 적용: 학습_14_NoSQL.md의 Step 1~9

## 공통 원칙

| 원칙 | 설명 |
|------|------|
| **왜 먼저** | "RDBMS로 안 되는 이런 경우에 NoSQL이 필요하다 (하지만 RDBMS가 기본)" |
| **비유 먼저** | NoSQL 유형/개념을 일상 비유로 직관 잡기 |
| **트레이드오프** | "NoSQL이 좋다"가 아니라 "이걸 얻고 저걸 포기한다" 명시 |
| **버전 차이** | MongoDB 4+(트랜잭션), 6+, 7+ 변경점 언급 |

### 비유 예시
```
RDBMS = "엑셀 표. 행과 열이 정해져 있음. 다른 시트와 VLOOKUP(JOIN) 가능"
Document DB = "서류 폴더. 폴더(문서)마다 내용이 달라도 됨. 관련 서류를 한 폴더에 함께 보관(임베딩)"
Key-Value = "사물함. 번호(키)로 물건(값)을 넣고 뺌. 안에 뭐가 있는지 검색은 안 됨"
Column-Family = "출석부. 날짜별로 출석 체크(시계열). 학생별로 안 보고 날짜별로 봄"
Graph DB = "인맥 지도. '홍길동의 친구의 친구'를 빠르게 찾음"
임베딩 = "여행 가방에 옷+세면도구+간식을 다 넣기(한 번에 꺼냄). 가방이 너무 크면 문제"
레퍼런싱 = "옷장/세면대/주방에 각각 보관(따로 찾아야 함). 하지만 공유 가능"
```

### 트레이드오프 예시
```
NoSQL 도입: 유연한 스키마+수평 확장 ↔ 조인 어려움, 트랜잭션 제한, 일관성 약화
임베딩: 조회 빠름(1번 읽기) ↔ 데이터 중복, 문서 크기 증가(16MB 제한)
레퍼런싱: 중복 없음 ↔ 조회 시 $lookup 필요(느림)
MongoDB 트랜잭션: 정합성↑ ↔ 성능 오버헤드, MongoDB 장점 상쇄
DynamoDB On-Demand: 자동 확장 ↔ 비용 예측 어려움
```

## 설명 흐름
1. **왜 써야 하는가**: "RDBMS로 이것이 안 될 때만 NoSQL" (RDBMS가 기본 전제)
2. **비유로 직관 잡기**: SQL ↔ NoSQL 매핑
3. **핵심 개념 + 명령어** (MongoDB: SQL 대응 표 활용)
4. **트레이드오프**: "이 DB를 선택하면 무엇을 포기하는가?"
5. **"이 데이터에 어떤 DB?" 판단 연습** → 사용자 참여
6. **오해하기 쉬운 부분 + 버전 차이**:
```
"NoSQL = RDBMS 대체" → 대체가 아니라 보완. 핵심 데이터는 여전히 RDBMS
"MongoDB는 스키마가 없다" → 스키마 없음 = 자유 ≠ 무질서. 앱 레벨 스키마 관리 필수
"NoSQL은 트랜잭션이 안 된다" → MongoDB 4+, DynamoDB 모두 트랜잭션 지원 (제약 있음)
"임베딩이 항상 좋다" → 문서 16MB 제한, Unbounded Array 위험
"DynamoDB는 쿼리가 자유롭다" → 설계 시 접근 패턴을 미리 결정해야 함. 유연하지 않음
MongoDB 4+: Multi-document Transaction 도입
MongoDB 6+: 변경 스트림 개선
```
7. **확인 질문**: 사용자 답변 → 피드백
```
Step 3: "이 데이터에 RDBMS vs NoSQL 중 무엇을 쓸 것인가? 4가지 기준으로 판단해보세요"
Step 5: "이 데이터를 임베딩할 것인가 레퍼런싱할 것인가? 근거는?"
Step 7: "DynamoDB의 Partition Key + Sort Key 역할은?"
Step 8: "NoSQL에서 정합성을 보장하는 전략 3가지는?"
Step 9: "채팅 메시지 저장에 어떤 DB를 쓸 것인가? 근거는?"
```
8. **정리 + 다음 안내**

## Step별 특이사항
- 기초 Step(1~3): RDBMS vs NoSQL 판단이 핵심. "4가지 기준" 프레임워크
- MongoDB Step(4~6): SQL ↔ MongoDB 매핑 + 문법 레퍼런스(문서에 포함)
- DynamoDB Step(7): AWS 연계, Partition Key/Sort Key 설계
- 트랜잭션 Step(8): "NoSQL은 트랜잭션 안 된다"는 오해 교정
- 실전 Step(9): 시나리오별 DB 선택 + 마이그레이션 전략
