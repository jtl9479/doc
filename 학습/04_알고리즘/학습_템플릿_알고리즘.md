> 적용: 학습_04_알고리즘.md의 Step 1~18

## 공통 원칙

| 원칙 | 설명 |
|------|------|
| **왜 먼저** | "왜 이 자료구조/알고리즘을 써야 하는가" (안 쓰면 시간 초과/메모리 초과) |
| **비유 먼저** | 알고리즘 동작을 일상 비유로 직관 잡기 |
| **트레이드오프** | 시간 vs 공간, 구현 복잡도 vs 성능 등 모든 풀이에 트레이드오프 명시 |

### 비유 예시
```
Big-O = "요리 시간 예측. '재료 n개일 때 요리 시간이 어떻게 늘어나는가?' O(1)=전자레인지(재료 수 무관), O(n)=순서대로 볶기, O(n²)=모든 재료를 서로 비교 맛보기"
배열 = "사물함 번호. 3번 사물함 바로 열기(O(1)). 중간에 끼워 넣으면 뒤에 다 밀어야 함(O(n))"
문자열 = "구슬 목걸이. Java String은 한번 꿰면 못 바꿈(불변). 바꾸려면 새로 만들어야(새 객체 생성)"
HashMap = "전화번호부. 이름(키)으로 번호(값)를 O(1)에 찾음"
투 포인터 = "양쪽에서 걸어오는 두 사람. 만날 때까지 좁혀감"
슬라이딩 윈도우 = "기차 창문. 창문(고정 크기)을 옆으로 밀면서 풍경(데이터) 관찰"
스택 = "접시 쌓기. 마지막에 올린 접시를 먼저 꺼냄(LIFO). 실행 취소(Undo)가 대표"
큐 = "줄 서기. 먼저 온 사람이 먼저 나감(FIFO). 대기열이 대표"
단조 스택 = "키 순서대로 줄 세우기. 앞 사람보다 크면 앞 사람 빠짐 → '다음 큰 원소' 찾기"
연결 리스트 = "보물찾기 게임. 각 장소(노드)에 다음 장소 힌트(포인터)가 있음. 3번째 장소를 가려면 1→2→3 순서로 따라가야 함"
정렬 = "카드 정리. Merge Sort=반씩 나눠서 각각 정리 후 합치기. Quick Sort=기준 카드 정하고 작은 것/큰 것 분류"
이진 탐색 = "숫자 맞추기 게임. '업/다운'으로 절반씩 줄여감"
트리 = "가계도/조직도. 루트(최상위) → 자식 → 손자. 계층 구조"
BST = "정리된 가계도. 왼쪽 자식 < 부모 < 오른쪽 자식. 찾기 빠름(O(log n))"
힙 = "우선순위 줄 서기. 가장 긴급한 사람(최소/최대)이 항상 맨 앞"
BFS = "물에 돌 던지기. 파문이 동심원으로 퍼짐(가까운 곳부터)"
DFS = "미로 탈출. 한 길로 끝까지 가보고, 막히면 되돌아와서 다른 길"
다익스트라 = "네비게이션. 현재 위치에서 가장 가까운 곳부터 확정하며 확장"
DP = "메모장에 답 적어두기. 같은 문제 다시 만나면 계산 안 하고 메모장 확인"
Union-Find = "동아리 합치기. '너는 어느 동아리?'(Find) + '두 동아리를 합친다'(Union). 경로 압축 = '회장이 누구야?' 물어볼 때 바로 회장에게 연결"
Trie = "자동완성. 'app'을 치면 'apple', 'application'이 나오는 이유. 글자 하나씩 트리를 타고 내려감"
그리디 = "뷔페. 매 순간 가장 맛있어 보이는 것부터 담음(전체 최적 보장 안 될 수도)"
백트래킹 = "스도쿠. 숫자 넣어보고, 안 되면 지우고 다른 숫자"
```

### 트레이드오프 예시
```
HashMap: O(1) 조회 ↔ 메모리 사용↑ + 해시 충돌 시 O(n) 최악
배열 vs 연결 리스트: 배열(인덱스 접근 O(1), 캐시 친화) ↔ 연결 리스트(삽입/삭제 O(1), 캐시 비친화)
정렬 후 이진 탐색: O(log n) 조회 ↔ 정렬 비용 O(n log n) 선투자
Merge Sort vs Quick Sort: Merge(안정, O(n log n) 보장) ↔ Quick(평균 빠름, 최악 O(n²))
BFS vs DFS: BFS(최단 경로 보장) ↔ DFS(메모리↓ 경로 탐색)
다익스트라 vs 벨만포드: 다익스트라(빠름, 양수만) ↔ 벨만포드(음수 가능, 느림)
DP (Bottom-up): 스택 오버플로 없음 ↔ 점화식 도출 어려움
DP (Top-down): 직관적 ↔ 재귀 스택 사용, 함수 호출 오버헤드
공간 최적화: 메모리↓ ↔ 코드 복잡도↑, 디버깅 어려움
그리디 vs DP: 그리디(빠름, 구현 단순) ↔ DP(최적해 보장, 느림)
```

## 설명 흐름

### 새 유형 첫 학습 시
1. **왜 써야 하는가**: "브루트포스면 O(n²)로 시간 초과. 이 패턴을 쓰면 O(n)"
2. **비유로 직관 잡기**: 위 비유 활용
3. **대표 문제로 패턴 설명**: 접근법 단계별 설명 + 코드 + 복잡도
4. **트레이드오프**: "이 풀이의 비용은?"
5. **오해하기 쉬운 부분**:
```
"HashMap은 항상 O(1)" → 해시 충돌 시 O(n). Java 8에서 트리화로 O(log n)
"Parallel Stream은 항상 빠르다" → 작은 데이터/공유 자원이면 오히려 느림
"DP = 재귀 + 메모이제이션만" → Bottom-up(반복문) 방식도 DP
"그리디가 되면 DP보다 항상 좋다" → 그리디가 최적해를 보장하는지 증명 필요
"정렬하면 무조건 좋다" → 정렬 O(n log n) 비용. 해시로 O(n)에 풀 수 있으면 불필요
"BFS는 DFS보다 좋다" → 최단 경로는 BFS, 경로 존재/모든 경우는 DFS가 적합
"다익스트라로 다 풀 수 있다" → 음수 가중치에서 동작 안 함. 벨만포드 필요
```
6. **확인 질문**: "이 유형인지 어떻게 아는가" + 키워드/단서 정리
```
"정렬된 배열 + 두 수의 합 → ?"  (투 포인터)
"연속 부분 배열의 최대 합 → ?"  (Kadane's / DP)
"최단 경로 + 양수 가중치 → ?"  (다익스트라)
"모든 경우를 탐색 + 가지치기 → ?"  (백트래킹)
"연결 요소/사이클 감지 → ?"  (Union-Find 또는 DFS)
"접두사 검색/자동완성 → ?"  (Trie)
"다음 큰 원소 → ?"  (단조 스택)
"Top K → ?"  (힙/우선순위 큐)
```

### 문제 풀이 시
1. **문제 제시** (정답 먼저 주지 않음)
2. **접근법 힌트** (사용자 요청 시, 단계적)
   - 힌트 1: "어떤 자료구조/패턴이 적합할까요?"
   - 힌트 2: "시간 복잡도 목표는 O(n)입니다"
   - 힌트 3: 핵심 아이디어 제시
3. **사용자 풀이 리뷰**
   - 정확성 (엣지 케이스 포함)
   - 시간/공간 복잡도 분석
   - 트레이드오프: "이 풀이의 비용은?"
   - 코드 스타일 피드백
4. **오해 확인**: "이 풀이에서 흔히 실수하는 부분" 짚기
5. **최적 풀이 제시** (사용자 풀이와 다른 접근이 있으면)
6. **확인 질문**: "이 문제를 O(n log n)이 아닌 O(n)으로 풀 수 있는가?" 같은 심화
7. **유사 문제 추천** (1~2개, 난이도 점진 상승)

## Step별 특이사항

### 기초 (Step 1)
- Step 1 (Big-O): 요리 시간 비유. "이 코드의 복잡도는?"을 반복 연습. "n이 10⁵이면 O(n²)는 가능한가?"(10¹⁰ → 불가) 판단 훈련

### 기본 자료구조 + 패턴 (Step 2~6)
- Step 2 (배열/문자열): 사물함 비유 + Prefix Sum, Kadane's 패턴
- Step 3 (해시맵): 전화번호부 비유. "O(n²) → O(n) 최적화의 90%는 HashMap"
- Step 4 (투 포인터/슬라이딩 윈도우): 두 사람 걸어오기 + 기차 창문 비유. "O(n²) → O(n)"
- Step 5 (스택/큐/덱): 접시 쌓기 + 줄 서기 비유. 단조 스택(키 순서 줄 세우기) 별도 설명
- Step 6 (연결 리스트): 보물찾기 비유. Fast-Slow 포인터(토끼와 거북이)

### 정렬/탐색 (Step 7~8)
- Step 7 (정렬): 카드 정리 비유. Java의 Arrays.sort(Dual Pivot Quick) vs Collections.sort(TimSort) 언급. "정렬은 전처리. 정렬 후 투 포인터/이진 탐색"
- Step 8 (이진 탐색): 숫자 맞추기 비유. off-by-one 경계 조건이 핵심. Parametric Search("답에 대한 이진 탐색") 패턴

### 트리 (Step 9~10)
- Step 9 (이진트리/BST): 가계도 비유. 순회(전위/중위/후위/레벨)를 "가계도 방문 순서"로. 재귀 사고 훈련
- Step 10 (힙/우선순위 큐): 우선순위 줄 서기 비유. "Top K"는 힙의 대표 활용. PriorityQueue 사용법

### 그래프 (Step 11~12)
- Step 11 (BFS/DFS): 물 파문(BFS) + 미로 탈출(DFS) 비유. 그리드 탐색(섬 개수), 위상 정렬(코스 선수과목)
- Step 12 (최단 경로): 네비게이션(다익스트라) 비유. "음수 가중치면 왜 다익스트라가 안 되는가?" 시나리오

### DP (Step 13~14)
- Step 13 (DP 기초): 메모장 비유. **"dp[i]가 무엇을 의미하는가"를 정의하는 것이 가장 중요**. 1차원 DP(Climbing Stairs, House Robber)
- Step 14 (DP 중급): 2차원 DP, 문자열 DP, 배낭. "점화식을 어떻게 도출하는가" 사고 과정을 단계별로

### 심화 (Step 15~16)
- Step 15 (Union-Find): 동아리 합치기 비유. 경로 압축 + 랭크 기반. "연결 요소/사이클"이 키워드
- Step 16 (Trie): 자동완성 비유. "HashMap과의 차이(접두사 검색)"

### 기타 (Step 17~18)
- Step 17 (그리디): 뷔페 비유. "그리디가 최적인지 판단"이 핵심. "반례를 찾아서 안 되면 DP"
- Step 18 (백트래킹): 스도쿠 비유. "선택 → 탐색 → 되돌리기" 3단계 코드 패턴

## 학습 방식 원칙
- 설명보다 **풀이 중심**. Claude가 긴 설명 < 사용자가 코드 짜는 시간
- 복잡도 분석을 **코드 작성 전에** 하는 습관 유도
- 매 풀이 후 **누적 문제 수 기록** (진행 상태 테이블 업데이트)
- 같은 유형 문제를 **3개 이상 연속 풀어야** 패턴이 체화됨
