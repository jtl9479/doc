# 아키텍처 설계 학습 템플릿

> 유형: **설계 연습 + 트레이드오프 토론 + 문서화**
> 적용: 학습_16_아키텍처설계.md의 Step 1~16

## 공통 원칙

| 원칙 | 설명 |
|------|------|
| **왜 먼저** | "설계 없이 코딩하면 6개월 후 이렇게 된다(기술 부채 폭발)" |
| **비유 먼저** | 아키텍처 개념을 일상 비유로 직관 잡기 |
| **트레이드오프** | 아키텍처 설계의 본질 = 트레이드오프. 정답 없음, 상황에 맞는 최선 |

### 비유 예시
```
아키텍처 = "건물 설계도. 벽 위치(모듈 분리)를 나중에 바꾸면 비용 폭발. 가구 배치(코드)는 쉽게 바꿈"
모듈러 모놀리스 = "아파트. 한 건물(하나의 배포) 안에서 벽으로 분리(모듈 격리). 리모델링(변경) 시 옆 세대에 영향 최소"
MSA = "타운하우스 단지. 각 집(서비스)이 독립. 하지만 택배/우편(통신) 관리가 복잡"
ADR = "회의록. '왜 이 결정을 했는가'를 기록. 6개월 후 '왜 이렇게 했지?' 하는 순간에 필요"
C4 Model = "지도 줌 레벨. 위성 사진(Context) → 시/구(Container) → 건물(Component) → 방(Code)"
YAGNI = "아직 손님이 10명인 식당에 100인분 주방 설비를 설치하지 마라"
```

### 트레이드오프 예시
```
모듈러 모놀리스: 단순+정합성 ↔ 독립 배포/확장 불가
MSA: 독립성↑ ↔ 복잡성+비용 3배↑
헥사고날: 유연↑ 테스트↑ ↔ 코드량↑ 인터페이스 과다
과도한 설계(Over-engineering): 미래 대비 ↔ 현재 생산성↓ 복잡성↑
부족한 설계(Under-engineering): 빠른 개발 ↔ 기술 부채 누적
비용 최적화: TCO↓ ↔ 성능/유연성 제약
```

## 설명 흐름

### 개념 Step (1~11)
1. **왜 알아야 하는가**: "이걸 모르면 설계에서 이런 실수"
2. **비유로 직관 잡기**: 20만 줄 프로젝트로 번역
3. **원칙 + 판단 기준 + 트레이드오프**
4. **오해하기 쉬운 부분**:
```
"설계를 완벽하게 해야 코딩을 시작한다" → BDUF(Big Design Up Front) 위험. 충분히 좋은(Good Enough) 설계 → 구현 → 피드백 → 개선
"MSA가 좋은 아키텍처다" → 상황에 따라 다름. 3명 팀 + 17 QPS에는 모듈러 모놀리스가 최적
"아키텍처 패턴을 하나만 적용해야 한다" → 모듈별로 다를 수 있음. 핵심=헥사고날, 단순=레이어드
"ADR은 귀찮은 문서 작업이다" → 6개월 후 '왜 이렇게 했지?'의 답. 없으면 같은 논의 반복
"비용을 고려하지 않아도 된다" → 시니어는 기술+비용+운영 공수를 함께 판단하는 사람
```
5. **확인 질문**: 사용자 답변 → 피드백
```
Step 4: "이 시스템의 기능/비기능 요구사항을 분리해보세요"
Step 5: "이 시스템의 QPS를 추정해보세요"
Step 6: "20만 줄 ERP에 어떤 아키텍처 패턴을 선택하는가? 근거는?"
Step 9: "이 시스템의 DB를 어떻게 선택하는가?"
Step 13: "이 설계의 병목/SPOF는 어디인가?"
Step 15: "이 ERP 시스템의 모듈 분리 + 트랜잭션 경계를 설계해보세요"
```
6. **"이 상황에서 A vs B?" 판단 연습** → 사용자 참여

### 설계 실전 Step (14~15): **정답을 먼저 주지 않음**
1. **요구사항 제시** (기능/비기능/제약조건)
2. **사용자 설계** (컴포넌트, 데이터 모델, 기술 선택)
3. **리뷰 + 트레이드오프 토론**: "왜? 대안은? 비용은?"
4. **ADR 작성 연습**: 핵심 결정 3가지를 ADR로
5. **C4 다이어그램 연습**

## Step별 특이사항
- 기초 Step(1~5): 프로세스 + 요구사항 + 추정. "ERP 200명 = 17 QPS, 확장성보다 정합성"
- 패턴 Step(6~8): "20만 줄에 어떤 패턴?" → 모듈러 모놀리스 + YAGNI
- 데이터 Step(9): 감사 로그 + 개인정보 아키텍처 (ERP 필수)
- 비기능 Step(10~11): 비용/운영 공수를 트레이드오프 축에 포함
- 문서화 Step(12): ADR + C4 + ArchUnit (코드로 규칙 강제)
- 평가 Step(13): TCO(Total Cost of Ownership) 관점 판단
- 20만줄 Step(15): 전체 종합 설계. 사용자가 설계 → Claude가 리뷰
