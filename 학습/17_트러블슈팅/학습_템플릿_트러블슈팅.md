# 트러블슈팅 학습 템플릿

> 유형: **장애 시나리오 → 진단 → 해결**
> 적용: 학습_17_트러블슈팅.md의 Step 1~14

## 공통 원칙

| 원칙 | 설명 |
|------|------|
| **왜 먼저** | "이 도구/프로세스를 모르면 프로덕션 장애 시 손도 못 댐" |
| **비유 먼저** | 진단 도구/프로세스를 일상 비유로 직관 잡기 |
| **트레이드오프** | 진단 도구/방법에도 트레이드오프 (정밀도 vs 오버헤드, 자동 복구 vs 근본 원인 은폐) |

### 비유 예시
```
트러블슈팅 = "의사 진료. 증상(로그/메트릭) 듣고 → 검사(덤프/프로파일링) → 진단(근본 원인) → 처방(해결) → 예방(재발 방지)"
Thread Dump = "순간 사진. 그 순간 모든 사람(스레드)이 뭘 하고 있는지 포착"
Heap Dump = "집 전체 인벤토리. 어떤 물건(객체)이 얼마나 공간을 차지하는지"
GC = "쓰레기 수거. 안 쓰는 물건(객체)을 치움. 수거 중에는 집 안(JVM)이 멈춤(STW)"
JFR = "블랙박스(비행기). 항상 기록 중. 사고 후 분석용. 성능 영향 거의 없음"
5 Whys = "의사의 문진. '열이 났다' → 왜? → '감기' → 왜 걸렸나? → '옷을 얇게 입음' → 왜? → 근본 원인 도달"
런북 = "응급 처치 매뉴얼. 비전문가(주니어)도 따라 할 수 있는 단계별 가이드"
카오스 엔지니어링 = "방재 훈련. 실제 화재(장애) 전에 미리 훈련해서 대응 능력 확인"
```

### 트레이드오프 예시
```
상세 로깅: 진단 정보↑ ↔ 디스크 사용↑ 성능↓
JFR 상시 기록: 사후 분석↑ ↔ 미미하지만 오버헤드 존재
자동 복구(HPA/Restart): 빠른 복구 ↔ 근본 원인 은폐 위험
자동 복구 안 함: 원인 분석 가능 ↔ 복구 지연 → 사용자 피해
Heap Dump 자동 생성: OOM 시 분석 가능 ↔ 덤프 생성 중 잠시 멈춤 + 디스크 사용
```

## 설명 흐름

### 개념/도구 Step (1~7)
1. **왜 알아야 하는가**: "이 도구 없이 이 장애를 만나면 손도 못 댐"
2. **비유로 직관 잡기**
3. **도구 사용법 + 출력 읽기** (덤프 예시, 로그 예시)
4. **트레이드오프**: "이 도구의 비용은?"
5. **오해하기 쉬운 부분**:
```
"로그만 보면 원인을 알 수 있다" → 로그는 1차 자료. 메트릭(추이), 덤프(내부 상태), 트레이스(경로)도 필요
"Thread Dump 1번이면 충분하다" → 3~5초 간격으로 3번 이상 떠야 추이 파악 가능
"OOM = 힙 부족" → Metaspace 부족, 네이티브 스레드 생성 실패도 OOM
"GC가 많으면 무조건 힙을 늘린다" → 메모리 누수면 늘려도 소용없음. Heap Dump로 누수 확인 먼저
"재시작하면 해결이다" → 임시 조치일 뿐. 근본 원인 안 찾으면 재발
"자동 복구 = 완벽한 대응" → 자동 복구는 근본 원인을 은폐할 수 있음. 알림 + 사후 분석 병행
```
6. **확인 질문**: 사용자 답변 → 피드백
```
Step 2: "장애 대응 5단계를 순서대로 설명해보세요"
Step 5: "이 Thread Dump에서 문제점은? (덤프 예시 제시)"
Step 6: "OOM이 발생하면 어떤 순서로 진단하는가?"
Step 8: "응답이 갑자기 느려졌다. 어떤 순서로 진단하겠는가?"
Step 10: "CPU 사용률이 높을 때 어떤 도구로 어떤 순서로 확인하는가?"
Step 13: "이 장애를 5 Whys로 분석해보세요 (시나리오 제시)"
```

### 시나리오 Step (8~12): **Claude가 정답을 먼저 주지 않음**
1. **장애 시나리오 제시**: "오후 2시, 이런 알림이 왔다. 어떻게 진단하겠는가?"
2. **사용자 진단** (사용자가 답변)
3. **피드백**: 진단 순서 적절성 + 놓친 부분 + 추가 정보 제공
4. **근본 원인 도달**
5. **대응 + 트레이드오프**: "임시 조치 vs 근본 해결"
6. **장애 보고서 작성 연습**

### 방법론 Step (13~14)
1. **장애 보고서 포맷 + 5 Whys + 런북 작성**
2. **실제 사례 분석**: "나라면 어떻게 진단?"

## Step별 특이사항
- 로그 Step(3~4): 구조화 로그 설계 + 에러 패턴 인식
- Thread/Heap/GC Step(5~7): 덤프 예시 보여주고 "문제점 찾기" 연습. Virtual Thread Pinning 진단
- Slow Response Step(8): JFR + JMC 활용
- 인프라 Step(10): lsof/tcpdump/strace (OS 레벨 진단)
- 카오스 Step(12): Docker에서 장애 주입 실습
- 런북 Step(13): "주니어도 대응 가능한 매뉴얼" + 자동 복구
