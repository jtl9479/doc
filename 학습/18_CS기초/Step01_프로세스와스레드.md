## 1. 비유로 직관 잡기

```
프로세스 = "독립된 집"
  - 각자 주방/거실/침실(메모리 공간)을 보유
  - 이웃과 벽(격리)으로 분리
  - 이웃에게 말을 전하려면 편지/전화(IPC)가 필요

스레드 = "한 집 안의 가족"
  - 주방/거실(Code, Data, Heap)은 공유
  - 방(Stack)만 각자 사용
  - 냉장고(공유 자원) 동시 접근 시 충돌 가능 → 동기화 필요

컨텍스트 스위칭 = "책 2권 번갈아 읽기"
  - 바꿀 때마다 "어디까지 읽었지?" 기억해야 함(오버헤드)
  - 다른 집 책(프로세스 전환) → 책상 전체 정리 필요(비용 큼)
  - 같은 집 책(스레드 전환) → 책갈피만 바꿈(비용 적음)
```

## 2. 핵심 개념

### 프로세스란

실행 중인 프로그램의 인스턴스. OS가 관리하는 작업 단위.

**프로세스 메모리 구조:**
```
┌──────────────────┐
│      Stack       │ ← 함수 호출, 지역 변수 (위에서 아래로 성장)
│        ↓         │
│                  │
│        ↑         │
│       Heap       │ ← 동적 메모리 할당 (아래에서 위로 성장)
├──────────────────┤
│      Data        │ ← 전역 변수, static 변수
├──────────────────┤
│      Code        │ ← 실행할 명령어 (텍스트 영역)
└──────────────────┘
```

- 각 프로세스는 **독립된 메모리 공간**을 가짐
- 한 프로세스가 죽어도 다른 프로세스에 영향 없음 (격리)
- 프로세스 간 통신은 **IPC**(Inter-Process Communication) 필요: 파이프, 소켓, 공유 메모리 등

### 스레드란

프로세스 내의 실행 흐름. 하나의 프로세스에 여러 스레드가 존재 가능.

**스레드 메모리 구조:**
```
┌─────────────── 프로세스 ────────────────┐
│  Code (공유)  │  Data (공유)  │  Heap (공유)  │
├───────────────┼───────────────┼───────────────┤
│  Stack (독립) │  Stack (독립) │  Stack (독립) │
│  [스레드 1]   │  [스레드 2]   │  [스레드 3]   │
└───────────────┴───────────────┴───────────────┘
```

- Code, Data, Heap은 **공유** → 통신이 쉬움 (별도 IPC 불필요)
- Stack만 **독립** → 각 스레드가 자신만의 함수 호출 스택 보유
- 공유 자원 접근 시 **동기화 문제** 발생 가능 (race condition)

### 프로세스 vs 스레드 핵심 차이

| 비교 항목 | 프로세스 | 스레드 |
|----------|---------|--------|
| **메모리** | 독립 (격리) | 공유 (Code/Data/Heap) |
| **생성 비용** | 높음 (메모리 공간 할당) | 낮음 (Stack만 할당) |
| **안정성** | 하나 죽어도 다른 프로세스 무관 | 하나 죽으면 전체 프로세스 영향 |
| **통신** | IPC 필요 (파이프, 소켓, 공유메모리) | 공유 메모리 직접 접근 |
| **동기화** | 불필요 (격리) | 필요 (공유 자원 경쟁) |

**트레이드오프:**
```
프로세스: 안정성↑(격리) ↔ 생성 비용↑ + 통신 비용↑(IPC)
스레드:   생성 비용↓ + 통신 쉬움 ↔ 안정성↓ + 동기화 필요
```

### 컨텍스트 스위칭

CPU가 현재 실행 중인 프로세스/스레드를 **다른 프로세스/스레드로 전환**하는 과정.

**동작 순서:**
1. 현재 상태 저장 (레지스터, PC, 스택 포인터 → PCB/TCB에 저장)
2. 다음 프로세스/스레드의 상태 복원 (PCB/TCB에서 읽어옴)
3. CPU가 새로운 프로세스/스레드 실행

**비용이 발생하는 이유:**
- 상태 저장/복원 자체의 시간
- **CPU 캐시 무효화** — 프로세스 전환 시 캐시에 있던 데이터가 새 프로세스와 무관 → 캐시 미스 급증
- TLB(주소 변환 캐시) 플러시

**프로세스 전환 > 스레드 전환 비용인 이유:**
- 프로세스 전환: 메모리 공간 자체가 바뀜 → 페이지 테이블 교체, TLB 플러시, 캐시 무효화
- 스레드 전환: 같은 메모리 공간 → Stack과 레지스터만 교체, 캐시/TLB 유지 가능

### PCB / TCB

| 구조 | 설명 | 저장 정보 |
|------|------|----------|
| **PCB** (Process Control Block) | 프로세스 상태 정보를 저장하는 OS 자료구조 | PID, 프로세스 상태, PC, 레지스터, 메모리 정보, 스케줄링 정보 |
| **TCB** (Thread Control Block) | 스레드 상태 정보를 저장하는 자료구조 | TID, 스레드 상태, PC, 레지스터, 스택 포인터 |

- 컨텍스트 스위칭 시 현재 PCB/TCB에 상태를 저장하고, 다음 PCB/TCB에서 상태를 복원

## 3. Java에서의 연결

| Java 개념 | OS 매핑 | 설명 |
|----------|---------|------|
| `Thread` (Platform Thread) | OS Thread와 **1:1 매핑** | 스레드 1개 = OS 스레드 1개. 생성 비용 ~1MB 스택 메모리 |
| `Virtual Thread` (Java 21+) | **M:N 매핑** (다수의 가상 스레드 : 소수의 캐리어 스레드) | 경량 스레드. 수십만 개 생성 가능. I/O 대기 시 캐리어 스레드 반환 |
| `synchronized` | OS 모니터 락 기반 | 공유 자원 동기화. 스레드 간 경쟁 시 컨텍스트 스위칭 발생 |
| `Thread.sleep()` | TIMED_WAITING 상태 | OS 스케줄러가 다른 스레드에게 CPU 할당 → 컨텍스트 스위칭 |

> **이것이 왜 중요한가**: Java 동시성을 공부할 때 "왜 스레드를 너무 많이 만들면 안 되는가?" →
> 스레드 = OS 스레드(1:1) → 생성 비용(~1MB 메모리) + 컨텍스트 스위칭 비용.
> 이것을 해결하려고 Virtual Thread(M:N)가 나온 것.

## 4. 오해하기 쉬운 부분

```
"프로세스가 스레드보다 안전하니까 항상 프로세스를 쓴다"
→ 프로세스 생성 비용↑ 통신 비용↑. 대부분의 경우 스레드를 사용.
  (Chrome은 탭마다 프로세스 = 안정성 우선. Java 서버는 스레드 = 성능 우선)

"컨텍스트 스위칭은 나쁘다"
→ 멀티태스킹에 필수. 비용을 줄이는 것이 목표.
  (경량 스레드/Virtual Thread로 전환 비용 절감)

"스레드가 많을수록 빠르다"
→ CPU 코어 수를 넘어가면 오히려 컨텍스트 스위칭 비용만 증가.
  CPU bound 작업: 코어 수만큼이 최적. I/O bound 작업: 더 많이 만들 수 있음.
```

## 5. 면접 답변

### 30초 답변

> 프로세스는 독립된 메모리 공간을 가진 실행 단위이고, 스레드는 프로세스 내에서 메모리를 공유하는 실행 흐름입니다.
> 핵심 차이는 메모리(독립 vs 공유), 생성 비용(높음 vs 낮음), 안정성(격리 vs 영향), 통신(IPC vs 직접 접근) 4가지입니다.
> 컨텍스트 스위칭은 CPU가 실행 주체를 전환할 때 상태를 저장/복원하는 과정이며, 프로세스 전환이 스레드 전환보다 비용이 큽니다.

### 2분 상세 답변

> 프로세스는 실행 중인 프로그램의 인스턴스로, OS가 관리하는 작업 단위입니다. 각 프로세스는 Code, Data, Heap, Stack으로 구성된 독립된 메모리 공간을 가집니다. 한 프로세스가 비정상 종료되어도 다른 프로세스에 영향을 주지 않는 격리성이 장점이지만, 프로세스 간 통신은 IPC(파이프, 소켓 등)가 필요해 비용이 높습니다.
>
> 스레드는 프로세스 내의 실행 흐름으로, 같은 프로세스의 스레드끼리 Code/Data/Heap을 공유하고 Stack만 독립입니다. 생성 비용이 낮고 통신이 쉬운 반면, 공유 자원에 대한 동기화가 필요하고 하나의 스레드 오류가 전체 프로세스에 영향을 줄 수 있습니다.
>
> 컨텍스트 스위칭은 CPU가 현재 실행 중인 프로세스/스레드의 상태(레지스터, PC, 스택 포인터)를 PCB/TCB에 저장하고, 다음 프로세스/스레드의 상태를 복원하는 과정입니다. 프로세스 전환이 스레드 전환보다 비용이 큰 이유는, 프로세스 전환 시 메모리 공간 자체가 바뀌어 페이지 테이블 교체와 CPU 캐시/TLB 무효화가 발생하기 때문입니다.
>
> Java에서는 Platform Thread가 OS 스레드와 1:1로 매핑되어 스레드 생성 비용이 ~1MB 수준입니다. Java 21의 Virtual Thread는 M:N 매핑으로 수십만 개의 경량 스레드를 만들어 컨텍스트 스위칭 비용을 줄입니다.
