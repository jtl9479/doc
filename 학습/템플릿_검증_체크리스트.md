# 템플릿 검증 체크리스트

> 각 기술별 학습 템플릿을 검증할 때 아래 항목을 순서대로 확인합니다.

---

## 1단계: 학습 MD 파일과 대조

| # | 확인 항목 | 확인 방법 |
|---|----------|----------|
| 1 | **Step 범위 일치** | 템플릿의 "적용: Step 1~N"이 학습 MD의 Step 목차 수와 일치하는가 |
| 2 | **모든 Step이 특이사항에 포함** | 학습 MD의 Step 1~N 각각이 템플릿의 "Step별 특이사항"에 매핑되어 있는가. 누락 없는가 |

---

## 2단계: 5대 공통 요소 확인

| # | 확인 항목 | 있어야 할 것 |
|---|----------|-------------|
| 3 | **왜 써야 하는가** | 공통 원칙 표에 "왜 먼저" 포함 + 설명 흐름 1단계에 반영 |
| 4 | **비유 예시** | 각 Step의 핵심 개념마다 비유가 있는가. Step 수 대비 비유 수가 충분한가 |
| 5 | **트레이드오프 예시** | 주요 선택/설정마다 "얻는 것 ↔ 잃는 것" 명시. 5개 이상 |
| 6 | **오해하기 쉬운 부분** | 기술별 흔한 오해 5개 이상. "~라고 생각하기 쉬운데, 사실은 ~" 형식 |
| 7 | **확인 질문 예시** | Step별 매핑된 면접/검증 질문. 주요 Step마다 1개 이상 |

---

## 3단계: 해당 기술에만 적용되는 항목 확인

| # | 확인 항목 | 해당 기술 |
|---|----------|----------|
| 8 | **버전 차이** | Java(8/11/17/21), Spring(Boot 2→3), DB(Oracle/Hibernate), Kafka(ZooKeeper→KRaft), Redis(6+), K8s(API 변경), NoSQL(MongoDB 4+) — 해당 기술이면 포함 확인 |
| 9 | **코드 예시 형식** | Java 코드(Java/Spring/테스트), SQL(DB), redis-cli(Redis), YAML(K8s/Docker), CLI(AWS/Docker) — 기술에 맞는 코드 형식이 명시되어 있는가 |
| 10 | **학습 방식 유형** | 개념+코드, 문제풀이, TDD실습, 설계연습, 시나리오진단, 도구실습, 면접Q&A 중 이 기술에 맞는 유형이 반영되어 있는가 |

---

## 4단계: 누락 점검

| # | 확인 항목 | 확인 방법 |
|---|----------|----------|
| 11 | **학습 MD에 있는데 템플릿에 없는 Step** | 학습 MD의 Step 목차를 하나씩 대조하여 템플릿 특이사항에 빠진 Step 찾기 |
| 12 | **학습 MD에 있는데 비유가 없는 핵심 개념** | 학습 MD의 각 Step 학습 항목 중 비유 없이 기술 용어만 있는 것 찾기 |
| 13 | **학습 MD에 있는데 확인 질문이 없는 Step** | 자가 검증 항목이 있는 Step에 대응하는 확인 질문이 템플릿에 있는지 |

---

## 검증 결과 보고 형식

```
### 점검 결과

| 점검 항목 | 결과 |
|----------|------|
| Step 범위 일치 | ✅ / ❌ |
| 5대 공통 요소 | 왜:✅ 비유:✅ 트레이드오프:✅ 오해:✅ 질문:✅ |
| 버전 차이 (해당 시) | ✅ / ❌ / 해당 없음 |
| Step별 특이사항 커버율 | N/N개 Step 커버 |
| 비유 커버율 | N개 비유 / N개 Step |
| 확인 질문 커버율 | N개 질문 / N개 Step |

### 보완 필요 N건
| # | 문제 | 설명 |
|---|------|------|
| 1 | ... | ... |
```
