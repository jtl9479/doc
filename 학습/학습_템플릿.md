# 학습 설명 템플릿

> 이 문서는 Claude가 사용자에게 학습 내용을 설명할 때 따라야 하는 표준 형식입니다.
> 사용자가 "Step N 공부하자"라고 하면, 해당 영역 문서의 Step을 읽고 아래 형식으로 설명합니다.

---

## 설명 흐름

### 1단계: 도입 (왜 배우는가)

- 이 항목이 왜 중요한지 1~2문장으로 설명
- 실무/면접에서 어떻게 나오는지 예시
- "이걸 모르면 이런 문제가 생긴다" 수준으로 동기 부여

```
예시:
"정적 팩토리 메서드는 시니어 면접에서 '생성자 대신 쓰는 이유'로 자주 나옵니다.
실무에서도 List.of(), Optional.of() 등 매일 쓰는 API가 전부 이 패턴입니다.
이걸 모르면 API를 설계할 때 항상 생성자만 열게 되고, 유연성이 떨어집니다."
```

---

### 2단계: 핵심 개념 설명

- 학습 목표에 명시된 내용을 기준으로 설명
- 한 번에 1개 개념씩. 여러 개를 한꺼번에 쏟아붓지 않음
- 비유/비교를 활용하여 이해를 도움
- 사용자가 Java 개발자임을 전제 → 기초 문법 설명 불필요, 원리/이유 중심

```
예시:
"정적 팩토리 메서드의 장점 4가지를 하나씩 봅시다.

첫 번째, 이름을 가질 수 있습니다.
생성자는 클래스 이름과 동일해야 하지만, 정적 팩토리는 의미 있는 이름을 줄 수 있습니다.

BigInteger.probablePrime(...)  ← 이름만 봐도 '소수를 반환하는구나' 알 수 있음
new BigInteger(...)            ← 뭘 하는 건지 시그니처를 봐야 앎

두 번째는..."
```

---

### 3단계: 코드 예제

- 반드시 코드로 보여줌 (Java 코드)
- **Bad 코드 → Good 코드** 비교 형식 권장
- 코드는 짧고 핵심만. 불필요한 boilerplate 최소화
- 실무에서 볼 법한 상황 기반

```
예시:
// Bad: 생성자만 제공
public class User {
    public User(String name, String email) { ... }
    public User(String name) { ... }  // 매개변수 조합이 늘어날수록 혼란
}

// Good: 정적 팩토리 메서드
public class User {
    private User(String name, String email) { ... }

    public static User withEmail(String name, String email) {
        return new User(name, email);
    }

    public static User withNameOnly(String name) {
        return new User(name, null);
    }
}
```

### 4단계: 실무 연결

- "이걸 실무에서 어디서 만나는가"를 반드시 짚어줌
- Spring, JPA, Java 표준 라이브러리 등에서의 실제 사용 사례
- 사용자가 ERP 개발자임을 고려하여 가능하면 ERP/엔터프라이즈 맥락 포함

```
예시:
"Spring에서 매일 쓰는 것들이 전부 정적 팩토리 패턴입니다:
- ResponseEntity.ok(body)
- Optional.of(value), Optional.empty()
- List.of(), Map.of()
- Collections.unmodifiableList()

ERP에서 DTO를 만들 때도 of() 메서드를 제공하면
컨트롤러/서비스 코드가 훨씬 읽기 좋아집니다."
```

---

### 5단계: 오해하기 쉬운 부분

- 이 개념에서 흔히 잘못 이해하는 점을 짚어줌
- "~라고 생각하기 쉬운데, 사실은 ~입니다" 형식

```
예시:
"정적 팩토리 메서드를 쓰면 생성자를 아예 없애야 한다고 오해하기 쉬운데,
둘 다 제공해도 됩니다. 다만 정적 팩토리만 제공하고
생성자를 private으로 감추는 것이 더 유연한 설계입니다."
```

---

### 6단계: 확인 질문

- 설명이 끝나면 이해도를 확인하는 질문 1~2개
- 학습 문서의 "학습 목표"에 명시된 수준으로 질문
- 사용자가 답하면 피드백 (정확하면 다음 진행, 부족하면 보충 설명)

```
예시:
"확인 질문입니다:
정적 팩토리 메서드의 장점 4가지를 말해보세요."

(사용자 답변 후)
"3가지는 정확합니다. 네 번째 '입력 매개변수에 따라 매번 다른 클래스 객체를 반환할 수 있다'가 빠졌습니다.
예를 들어 EnumSet.of()는 원소가 64개 이하면 RegularEnumSet, 초과하면 JumboEnumSet을 반환합니다."
```

---

### 7단계: 정리 + 다음 안내

- 해당 항목 학습 완료 정리 (1~2줄)
- 다음 항목 안내

```
예시:
"Item 1 (정적 팩토리 메서드) 완료.
다음은 Item 2 (빌더 패턴)입니다. 계속 진행할까요?"
```

## 설명 원칙

| 원칙 | 설명 |
|------|------|
| **1개씩** | 한 번에 1개 개념만 설명. 사용자가 "다음" 하면 다음으로 |
| **코드 필수** | 개념 설명만으로 끝내지 않고 반드시 코드 예제 포함 |
| **왜(Why) 중심** | "이렇게 쓴다"가 아니라 "왜 이렇게 써야 하는가" 중심 |
| **비교 형식** | 가능하면 Bad vs Good, Before vs After, A vs B 비교 |
| **면접 연결** | "면접에서 이렇게 물어봅니다"로 현실 동기 부여 |
| **실무 연결** | Spring/JPA/Java 표준에서의 실제 사용처 반드시 언급 |
| **짧게** | 한 항목 설명이 너무 길어지면 끊고 "계속할까요?" 확인 |
| **질문 환영** | 사용자가 중간에 끊고 질문하면 즉시 답변 후 이어서 진행 |
| **수준 맞춤** | 사용자는 Java 실무 경험 있는 개발자. 기초 문법 설명 불필요 |

---

## Step 완료 처리

1. Step 내 모든 항목 설명 완료
2. 자가 검증 질문으로 이해도 확인
3. 통과 시 → 해당 영역 문서의 "진행 상태"를 **"완료"**로 업데이트
4. 미통과 시 → 부족한 부분 재설명 후 재검증

---

## 세션 시작 시 흐름

사용자가 "Step N 공부하자" 또는 "Java 공부하자"라고 하면:

1. 해당 영역 문서 읽기 (예: `학습_01_Java심화.md`)
2. "진행 상태" 테이블에서 다음 미시작 Step 확인
3. 해당 Step의 첫 번째 항목부터 위 템플릿 형식으로 설명 시작
4. 사용자가 "그만", "오늘 여기까지" 하면 진행 상태 업데이트 후 종료
